# MVU Lite 小卡教程

MVU Lite 是给新作者使用的轻量 MVU 写法。它不是 MVU ZOD 的简化版，而是挂在 MVU beta 上的一层中文解析器。

世界书条目前缀仍然使用 MVU 原本的 `[mvu_update]`，因为它负责让 MVU 进入额外变量解析流程。Lite 只改变变量规则和输出格式的写法，不改变 MVU 的条目识别入口。

作者只需要学会三件事：

- 写开局变量
- 写一排排纯中文变量规则
- 固定复制变量列表、输出格式和脚本模板

复杂卡、动态对象、复杂校验仍建议使用 MVU ZOD。MVU Lite 只负责最基础的小卡变量。

---

## 1. 安装脚本

在酒馆助手脚本里新建脚本，例如命名为 `MVU Lite变量约束`，填入：

```js
import 'https://testingcf.jsdelivr.net/gh/MagicalAstrogy/MagVarUpdate@beta/artifact/bundle.js';
import { 注册轻量MVU } from 'https://testingcf.jsdelivr.net/gh/sanmingyue/tavern_dist@mvu-lite-v0.0.4/dist/mvu-lite/index.js';

const 变量规则 = `

始.好感度：数字；范围0到100；单次变化最多5；只有始明确感知到{{user}}行为并改变态度时更新。
始.情绪：选项：平静、警惕、动摇、依赖；根据始在当前互动里的即时反应更新。
始.当前所想：文字；一句话，贴近始当下反应，每轮可以更新。
世界.当前地点：文字；场景变化时更新。
世界.当前时间：文字；时间推进时更新。

`;

$(() => {
  注册轻量MVU({ 变量规则 });
});
```

作者只需要修改 `const 变量规则 = \`...\`` 中间的内容。

## 2. 初始变量

世界书条目名建议：

```txt
[initvar]变量初始化勿开
```

条目必须禁用。MVU 会读取禁用的 initvar 条目作为开局变量。

示例：

```yaml
始:
  好感度: 30
  情绪: 警惕
  当前所想: 先确认眼前的人是否危险
世界:
  当前地点: 第一层·起始之间
  当前时间: 08月16日 09:00
```

## 3. 变量列表

世界书条目名建议：

```txt
变量列表
```

内容固定照抄：

```yaml
---
<status_current_variables>
{{format_message_variable::stat_data}}
</status_current_variables>
```

它负责把当前变量展示给 AI。

## 4. 变量更新规则

世界书条目名建议：

```txt
[mvu_update]变量更新规则
```

内容用纯中文，一行一个变量：

```txt
始.好感度：数字；范围0到100；单次变化最多5；只有始明确感知到{{user}}行为并改变态度时更新。
始.情绪：选项：平静、警惕、动摇、依赖；根据始在当前互动里的即时反应更新。
始.当前所想：文字；一句话，贴近始当下反应，每轮可以更新。
世界.当前地点：文字；场景变化时更新。
世界.当前时间：文字；时间推进时更新。
```

推荐句式：

```txt
变量路径：类型；限制；更新条件。
```

目前支持的类型：

```txt
数字
文字
选项
布尔
```

数字变量可以写：

```txt
角色.好感度：数字；范围0到100；单次变化最多5；根据当前互动更新。
```

选项变量可以写：

```txt
角色.情绪：选项：平静、警惕、动摇、依赖；根据当前互动更新。
```

文字变量可以写：

```txt
角色.当前所想：文字；最多40字；一句话，贴近当前心理。
```

布尔变量可以写：

```txt
角色.是否知道秘密：布尔；只能填写是或否；开局通常为否；只有剧情中秘密被明确说出、展示或被角色亲自发现时，才改为是。
```

布尔变量适合记录“是否发生过”的状态，例如是否见过面、是否交换联系方式、是否知道某个秘密。不要用它记录程度变化，程度变化应该用数字或选项。

只读变量可以写：

```txt
角色.姓名：文字；只读；不要更新。
```

## 5. 变量输出格式

世界书条目名建议：

```txt
[mvu_update]变量输出格式
```

内容固定照抄：

为了兼容常见正则和预设捕获，Lite 固定使用通用标签 `<UpdateVariable>`。

```yaml
---
变量输出格式:
  rule:
    - 每次回复结尾如果变量需要变化，必须输出轻量变量更新。
    - 只能使用“改为”“增加”“减少”三种动作。
    - 没有变化的变量不要输出。
    - 不要更新变量规则中不存在的路径。
    - 数字变量必须遵守范围和单次变化上限。
    - 选项变量只能改为变量规则里列出的选项。
  format: |-
    <UpdateVariable>
    变量路径：改为新值；原因：原因
    变量路径：增加数字；原因：原因
    变量路径：减少数字；原因：原因
    </UpdateVariable>
```

AI 最终应输出成这样：

```txt
<UpdateVariable>
始.好感度：增加3；原因：始对{{user}}的戒备略微下降。
始.情绪：改为动摇；原因：她开始怀疑自己的判断。
始.当前所想：改为他好像不是敌人，但还不能完全相信。
世界.当前时间：改为08月16日 09:20；原因：对话和探索经过了一段时间。
</UpdateVariable>
```

脚本会在 MVU 写入前检查这些更新：

- `始.好感度：增加999` 会被限制为最多增加 5。
- `始.好感度：改为120` 会被压到 100。
- `始.情绪：改为崩溃` 如果不在选项里，会被忽略。
- 未写入变量规则的路径会被忽略。

默认情况下，脚本会在变量写入前清理 `<UpdateVariable>...</UpdateVariable>`，避免污染正文。

## 7. 第一版限制

MVU Lite 第一版故意只做基础能力：

- 不支持数组插入
- 不支持对象动态增删
- 不支持 move
- 不支持复杂 Zod 校验
- 不支持旧值对比触发复杂事件

如果角色卡需要物品栏、任务列表、动态 NPC、复杂地图状态，建议升级到 MVU ZOD。
