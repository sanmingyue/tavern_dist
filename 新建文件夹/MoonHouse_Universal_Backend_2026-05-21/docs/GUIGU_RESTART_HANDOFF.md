## 3. 月之屋后端定位

月之屋继续作为所有未来 AIRP 项目的通用 AI 后端。

它负责：

- OpenAI-compatible API 调用。
- 模型列表获取和选择。
- 聊天预设。
- 世界书扫描。
- 提示词宏。
- 提示词后处理。
- 工具/函数调用框架。
- 长期记忆、总结、用户画像。
- 本地存档。
- 游戏前端临时注入。
- AI 输出解析。

它不负责：

- 游戏画面。
- 地图移动。
- 角色战斗。
- 背包 UI。
- 任务 UI。
- 技能树 UI。
- 美术风格。
- 玩法数值平衡。

前端只需要把“当前场景、玩家动作、NPC、地点、数值变化、事件结果”交给月之屋，月之屋返回正文、NPC 发言、可解析的结构化结果。

## 4. 新项目核心方向

目标类型：

修仙开放世界 / 类鬼谷八荒 / 单机本地 AIRP 沙盒 RPG。

第一阶段不要做大而全，先做最小闭环：

1. 大地图。
2. 地点。
3. 玩家角色。
4. NPC。
5. 时间推进。
6. 移动。
7. 遭遇事件。
8. AI 正文反馈。
9. 简单战斗或事件结算。
10. 本地存档。

建议第一版叫“垂直切片”，只做一个小区域，例如：

- 一个州。
- 三个地点。
- 五个 NPC。
- 三种事件。
- 一个宗门。
- 一个城镇。
- 一个野外区域。

## 5. 新前端与月之屋的交互方式

Unity 前端每次发生重要动作时，生成一个 `GameTurnRequest`：

- 玩家是谁。
- 当前地点。
- 当前时间。
- 当前 NPC。
- 玩家动作。
- 本地结算结果。
- 可见状态。
- 需要 AI 叙述什么。

月之屋返回：

- 正文。
- NPC 台词。
- 隐藏标签清理后的玩家可见文本。
- 可选的结构化状态补丁。
- 可选的记忆提示。
- 可选的下一步选择。

设计原则：

本地数值由 Unity 决定，AI 不直接乱改核心数值。

AI 可以解释结果、补充人物反应、生成事件气氛、给出对话和后续钩子。

## 6. 新玩法模块建议

第一层，世界和移动：

- 大地图节点。
- 地点类型：城镇、宗门、野外、秘境、坊市、洞府。
- 时间：日、时辰、天气。
- 移动消耗：时间、精力、风险。

第二层，角色：

- 玩家属性：寿元、境界、修为、灵力、体力、悟性、魅力、声望。
- NPC 属性：境界、门派、关系、性格、目标、记忆。
- 关系：好感、仇恨、恩情、交易、师徒、道侣、宗门关系。

第三层，修仙：

- 境界。
- 功法。
- 神通。
- 突破。
- 丹药。
- 灵根。
- 瓶颈。
- 心魔。

第四层，事件：

- 随机遭遇。
- NPC 主动事件。
- 宗门事件。
- 城镇传闻。
- 秘境探索。
- 追杀与救援。
- 拍卖与交易。

第五层，AI：

- NPC 对话。
- 地点正文。
- 遭遇描写。
- 战斗后叙述。
- 任务文本。
- 传闻生成。
- 角色记忆更新。

## 7. 美术与 UI 方向

优先级按当前决定：

1. 美术素材。
2. UI 参数、字体、布局。
3. Shader 和材质。
4. 代码。

生图素材规则：

- 纯色背景，方便抠图。
- 主体居中，四边留安全边距。
- 不要贴边。
- 不要让阴影、衣摆、武器超出画布。
- UI 切片要无文字。
- 按钮、面板、边框、图标尽量做成可复用素材。
- 九宫格面板要有清晰边框和干净中心区域。
