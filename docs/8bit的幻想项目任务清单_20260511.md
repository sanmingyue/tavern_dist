# 8bit的幻想项目任务清单

## 0. 项目定位

### 0.1 核心概念

项目正式名: **8bit的幻想**。

玩家 `{{user}}` 意外捡到一块 8bit 风格的手表。手表瞬间锁定在右手腕，随后响起 8bit 时代的古早勇者冒险旋律。玩家被卷入一个原创的、真实存在的 8bit 世界。

这个世界不是现实世界，也不是单纯的怀旧滤镜。它是成年人儿时勇者梦的具象化：像素村庄、方块怪物、简洁却庄严的冒险地图、任务、伙伴、升级、装备、魔王城、四天王、精灵与矮人等种族，以及那个名为莱姆的魔王。

整体气质参考古早勇者冒险的王道热血，但不照搬具体作品。它的核心浪漫是 8bit 时代的幻想：小时候握住手柄时相信自己真的能成为勇者，长大后又在某个瞬间被那段音乐、那块屏幕、那种像素光芒重新叫醒。

世界规则：

- `{{user}}` 进入 8bit 世界后也会变成 8bit 形态。
- 8bit 世界的人如果被带入现实世界，会变成现实风格的样子。
- 8bit 形态是玩家视角中的呈现方式；对 8bit 世界原住民而言，他们并不觉得自己发生了"画风变化"。
- 现实世界与 8bit 世界都是真实世界，不是梦境或纯游戏模拟。
- 8bit 世界可以像游戏一样拥有菜单、等级、地图、职业、魔王城等结构，但世界内角色是真实存在的生命。
- 现实世界与现实规则一致，剑与魔法在现实世界无效，最多保留体格、训练、反应、气质等非魔法层面的影响。
- 最终魔王决战存在一次性的唯心突破剧情，防止滥用；具体描写与触发文本由用户未来写到该阶段时提供。
- 主线故事可以提前完整规划到魔王城前与最终决战入口，但莱姆个人故事、大结局、最终决战核心文本由用户亲自提供。

核心身份：

- 勇者: `{{user}}`。
- 魔王: 莱姆。
- 莱姆性别: 女。
- 莱姆详细人设: 留空，后续由用户单独提供。
- 手表正式名: `8 bit`。

### 0.2 技术定位

- 酒馆作为后端与 AI 生成入口。
- 前端作为玩法客户端与规则裁判。
- chat 变量作为单局存档数据库。
- 角色卡 / 世界书 / 注入作为叙事、知识路由与存档内容扩展。
- AI 负责叙述、NPC 扮演、气氛、对白、剧情补全。
- AI 负责在需要进入新场景前生成该场景 NPC 设计，并写入当前存档对应的世界书。
- AI 可根据当前情况生成成就文案，由脚本解析并写入成就栏。
- AI 不负责经验、战斗伤害、掉落、装备、任务状态、地图移动等权威结算。
- 项目内置 API 接口层，复刻酒馆式获取/选择体验，允许用户使用酒馆当前接口，也允许为不同功能选择不同接口配置。
- 一个存档绑定一个世界书；切换或导入存档时，要能恢复该存档对应的世界书内容。

### 0.3 不做什么

- 不对照戴森球项目逐项复制。
- 不复用戴森球 UI。
- 不把勇者斗恶龙等作品的具体设定照搬进项目。
- 不让 AI 直接改变量或输出存档指令。
- 不依赖真实现实时间 `Date.now()` 推进玩法。
- 不在第一版一次性做完整大世界。
- 不把 AI 调用限制成"玩家发一次，AI 回复一次"。AI 还要承担 NPC 写入、场景补全、同伴行动叙述、正文转化等内容生产工作。

### 0.4 第一版最小闭环

- 玩家能打开全屏前端。
- 玩家能创建现实身份，并把角色定义写入世界书。
- AI 能根据玩家填写的现实身份生成最合理的开场白。
- 前端能在现实世界 UI 与 8bit 世界 UI 之间切换。
- 手表能作为地图与菜单入口。
- 玩家能看到状态、队伍、背包、任务、地图。
- 玩家能移动到少量地点。
- 玩家能遭遇怪物并完成基础战斗。
- 玩家能获得经验、金币、物品。
- 玩家能升级。
- 玩家能接取并推进一条主线与少量支线。
- AI 能根据权威局势摘要进行旁白与 NPC 扮演。
- 存档能保存到 chat 变量，刷新后继续。
- 主线目标能明确指向魔王莱姆，但第一版不要求最终决战。
- 第一版要预留职业、转职、伙伴死亡、世界书写入、API 配置接口。
- 第一版要预留成就系统接口。

## 1. 总体原则

### 1.1 玩法权威

所有确定性玩法结果由前端脚本结算：

- 等级与经验。
- HP / MP / 属性。
- 职业、转职、洗点、技能学习。
- 战斗胜负。
- 怪物掉落。
- 金币与道具。
- 装备穿戴。
- 任务接取、推进、完成。
- 地图移动。
- 伙伴入队、离队、站位。
- 现实世界与 8bit 世界状态切换。
- 手表功能解锁。
- 伙伴死亡与队伍状态。

AI 回复只作为消息、旁白、对白、气氛与内容草稿，不直接成为权威数值状态。

允许 AI 做的高价值工作：

- 生成 NPC 草案并写入当前存档世界书。
- 根据脚本给出的战斗操作日志写成正文。
- 根据同伴人设选择合理行动建议或叙述，但最终行动与结果必须被脚本校验。
- 生成地点氛围、居民反应、莱姆相关伏笔、现实世界放松段落。

### 1.2 模块边界

每个模块必须独立：

- `types`: 对外公开类型与接口。
- `data`: 静态配置数据。
- `engine`: 规则结算。
- `selectors`: 只读派生状态。
- `tests` 或调试入口: 关键规则验证。

模块之间不能随意直接改对方数据。跨模块修改必须通过统一 `Action` 或明确的模块接口。

### 1.3 可扩展优先

第一版可以小，但接口必须为后续扩展留位置：

- 怪物可以从 3 种扩到 300 种。
- 地图可以从 4 个地点扩到大陆、海域、塔、迷宫、魔王城。
- 伙伴可以从 0 个扩到完整队伍系统。
- 任务可以从固定任务扩到任务链、隐藏任务、分支任务。
- 装备可以从基础数值扩到词条、稀有度、套装。
- 现实世界可以从少量状态扩到完整现实线剧情。
- 职业可以从基础勇者扩到多层职业树。
- 种族、国家、秘境、四天王、魔王城均应数据化，不写死在 UI 中。

### 1.4 时间规则

本项目不使用真实现实时间推进玩法。

项目内存在两套设定时间：

- `realityTime`: 设定里的现实世界时间。
- `eightBitTime`: 8bit 世界时间。

时间倍率：

- 8bit 世界 24 小时 = 设定现实世界 3 小时。
- 即 8bit 世界时间流速为设定现实世界的 8 倍。
- 只有玩家处于 8bit 世界时，两个世界按倍率推进。
- 玩家处于现实世界时，8bit 世界完全暂停。

时间推进来源：

- AI 回复中携带或暗示的叙事时间戳。
- 前端解析并校验时间戳。
- 脚本决定是否接受时间推进。
- 特殊剧情事件可主动推进时间。

安全边界：

- 不允许无条件倒流。
- 不允许普通回复一次跳过过长时间。
- 不允许 AI 通过时间戳伪造战斗、任务或奖励结果。
- 时间变化要记录来源与原因，便于调试。
- 战斗中不能返回现实世界。
- 只有脱离战斗状态时，玩家才能回到现实世界。

### 1.5 UI 与图标规则

- 所有 UI 都不使用 emoji。
- 按钮图标、状态标记、地图标记、地块图形、战斗标记、背包/装备占位图都使用 SVG 或 CSS 形状绘制。
- 8bit 世界 UI 可以使用像素块、网格、描边、低色阶、扫描线、方形图标，但不能用 emoji 充当图标。
- 现实世界 UI 走正常现代界面，也同样不使用 emoji。
- AI 生成内容可以写叙述文本，但如果要给前端解析为 UI 标记，必须输出脚本约定的结构化字段或地图符号，不输出 emoji。
- UI 整体风格采用 P5（Persona 5）风格：红黑配色、斜切排版、动感过渡、角色立绘与菜单分列布局。

## 3. 存档结构草案

主存档存放在 `chat` 变量中。

```ts
interface GameSave {
  version: number;
  projectName: '8bit的幻想';
  createdAtStoryTime: StoryTime;
  lastAcceptedTimestamp: StoryTime | null;
  mode: 'reality' | 'eight_bit';
  creation: CharacterCreationState;
  player: PlayerState;
  experience: ExperienceState;
  profession: ProfessionState;
  party: PartyState;
  map: MapState;
  inventory: InventoryState;
  equipment: EquipmentState;
  combat: CombatState;
  mainQuest: MainQuestState;
  sideQuest: SideQuestState;
  npc: NpcState;
  watch: WatchState;
  reality: RealityState;
  narration: NarrationState;
  achievement: AchievementState;
  api: ApiProfileState;
  worldbookMemory: WorldbookMemoryState;
  messages: GameMessage[];
  debug: DebugState;
}
```

存储原则：

- `chat` 变量: 当前一局游戏权威存档。
- `character` 变量: 跨聊天长期设定，如已解锁主题、默认难度、莱姆长期偏好。
- `script` 变量: UI 设置，如音量、窗口模式、像素缩放、动效开关。
- `message` 变量: 可选楼层快照，不作为主存档。
- 世界书: 当前存档的 NPC、地点记录、现实身份、剧情记忆、已生成内容。
- 存档与世界书必须一一对应；导入存档时要能导入或恢复对应世界书。

角色创建写入规则：

- 开局由用户填写 `{{user}}` 的现实身份、姓名/称呼、现实起点、基础偏好。
- 创建完成后写入世界书。
- 世界书条目设置要求: 蓝灯、角色定义前、顺序 1、勾选进一步递归、勾选防止递归。

### 5.4 Player: 玩家属性

目标：

- 管理玩家基础属性与派生属性。
- 支持后续职业、称号、异常状态扩展。
- 开局创建角色时由用户自由填写现实身份，并将该身份写入世界书。
- `{{user}}` 在现实世界是现实形态，进入 8bit 世界后转化为 8bit 形态。
- 创建人物不做问卷式引导，只提供一个 8bit 外框与一本书风格的自由输入框。
- 用户确认后写入世界书。
- 写入完成后，AI 根据用户填写的现实身份、气质、处境与自由文本生成最合理的开场白。
- 开场白结束后进入 `8 bit` 锁定、音乐响起、穿越到 8bit 世界的流程。

基础属性：

- 等级。
- HP。
- MP。
- 力量。
- 体质。
- 智力。
- 精神。
- 敏捷。
- 技巧。
- 幸运。
- 意志。

派生属性：

- 物理攻击。
- 物理防御。
- 魔法攻击。
- 魔法防御。
- 速度条增长。
- 命中。

## 版本拆分长期原则（2026-05-16）

本节用于纠偏旧记录中“2.0 等于终章”或“2.x 快速切到结局”的误读。`8bit的幻想` 是超大型 8bit 幻想开放世界，版本拆分的目的，是让 V1.0 先封闭测试运行，后续内容按章节 / DLC 式内容包 / 大版本阶段分批制作、分批导入、分批更新。

- V1.0 已经进入封闭测试，正式运行代码、任务封包、地图、怪物、奖励、世界书导出不因 2.0 规划而改动。
- 大版本按章节主题和开放世界阶段拆分，不按单个地图、几条主线任务或几个支线机械碎切。
- 2.0、3.0、4.0 以及后续版本是一条长期更新路线，不是快速通关路线，也不是把整个世界观压缩到几个版本里完结。
- 每个大版本都必须登记：章节名、主线推进范围、地图开放范围、NPC 与势力、怪物与 Boss、支线 / 循环 / 隐藏 / 掉落 / 特殊任务池、素材需求、世界书需求、验收边界。
- 主线负责引导玩家去到当前大版本的每一个重要地点、地图、区域、秘境和势力节点；支线负责把这些地点写厚，但支线池不等于全部内容量。
- 支线池必须同时区分固定 NPC 支线、地区支线、隐藏任务、掉落触发任务、特殊触发任务、循环任务、职业与种族任务、NPC 链条、地图生态、怪物、材料、装备和秘境前置。
- 现有支线正文和公式书只视为“当前内容池”，不是最终体量。用户尚未写完的支线、莱姆相关深层内容、真正终章内容，一律标记为“用户后续补写 / 远期保留”。
- 2.0 和 2.x 不得过早接近最终门、最终战、莱姆完整人设、莱姆真实动机、最终战机制或真正结局。
- 魔王城内部、最终战、莱姆深层真相、最终门后的内容和大结局，除非用户明确补写并确认解锁，否则只允许做边界标记和远期保留，不允许代写完成。
- 新建的 `src/8bit的幻想/2.0` 只能作为未来更新暂存 / 策划 / 素材清单 / 世界书草案使用；正式更新时再由用户确认迁移，不能直接并入 V1.0 正式运行内容。
