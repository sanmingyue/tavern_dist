# 古风大世界项目清单

> 本文件用于先定模块边界和讨论顺序。当前阶段只拆项目，不扩写世界观、不写最终前端 UI、不改任何参考源文件。

## 0. 项目定位

本项目是一张以酒馆为启动器的大型 AIRP 角色卡。核心运行思路：

- 酒馆只提供启动、模型调用、脚本加载、必要的聊天记录能力。
- 前端脚本是玩法客户端和规则裁判。
- AI 只负责叙述、角色互动、气氛、建议和可控的创意补全。
- 所有会影响连续玩法的权威状态由脚本结算，不交给 AI 裁决。
- 存储优先放在浏览器缓存中，用存档槽区分不同游戏数据。
- 前端部分先只做接口和数据流，等脚本、公式、预设、提示词、资源路由都稳定后再做正式界面。

本项目用途：

- 不做多阶段人设。
- 生成结果用于 NPC 一致性：基础信息、别名、关系入口、外貌、性格、动机、日程倾向、初始记忆、可触发标签。

- 资源目录按规则层、世界总纲、地域、地点、势力、NPC、玩法规则、事件等分组。

## 3. 模块总清单

### M00 来源隔离与复制策略

职责：

- 建立 `vendor/` 或等价复制目录。
- 所有外部参考代码只读，引用前先复制。
- 记录复制来源、复制时间、删改点、保留点。

产物：

- `vendor/README.md`
- `PROJECT.md` 中的来源变更记录。

讨论点：

- 哪些来源需要先复制，哪些只看文档。

### M01 项目骨架与入口脚本

职责：

- 建立酒馆助手脚本入口。
- 脚本加载后只完成初始化、存档选择入口、服务注册、接口暴露。
- 前端先做极简壳，不做正式玩法界面。

产物：

- `index.ts`
- `App.vue`
- `stores/gameStore.ts`
- `stores/uiStore.ts`

验收：

- 脚本能加载、卸载、清理监听。
- 有打开/关闭入口。
- 不阻塞酒馆。

### M02 浏览器缓存存档系统

职责：

- 所有权威存档放浏览器缓存。
- 开局必须进入存档选择：新建、读取、复制、删除、导入、导出。
- 不同存档槽隔离所有缓存数据。
- 存档读取必须经过 zod schema 校验和迁移。

建议存储：

- `localStorage`: 存档索引、当前激活存档 ID、轻量设置。
- `IndexedDB`: 大型存档、资源缓存、历史快照、日志。

建议 key：

- `gufeng-world/save-index`
- `gufeng-world/active-save-id`
- `gufeng-world/save/{saveId}`
- `gufeng-world/settings`
- `gufeng-world/resource-cache/{resourceVersion}`

产物：

- `services/browserSaveService.ts`
- `services/saveMigrationService.ts`
- `schema.ts`

验收：

- 刷新后能继续同一存档。
- 切换存档后 NPC、背包、地图、记忆互不串档。
- 导入旧版本存档能迁移或回退到安全初始存档。

### M03 权威存档 Schema

职责：

- 定义世界状态、玩家状态、NPC、资源、战斗、任务、经营、记忆、日志。
- 所有 engine 写入都以 `GameSaveSchema.parse()` 或局部 schema 校验收口。
- 字段先留结构，不填内容细节。

初始建议域：

- `meta`: schemaVersion、saveId、createdAt、savedAt、contentVersion。
- `player`: 身份、外观、属性、背包、当前位置、关系总览。
- `world`: 时间、天气、阶段、已探索地点、世界事件。
- `locations`: 已解锁区域、地点状态、资源点状态。
- `npcs`: 配角/美女/高手/商人/敌人的统一档案。
- `collection`: 美女收集、高手收集、图鉴、招募状态。
- `relationship`: 好感、忠诚、恐惧、恩义、互动记忆。
- `economy`: 货币、产业、店铺、收益、支出、市场。
- `combat`: 当前战斗、历史战报、战斗冷却。
- `quests`: 主线、支线、委托、日常、奇遇。
- `memory`: 大总结、角色记忆、动态人设、玩家行为模式。
- `logs`: actionLog、systemLog、debugLog。

产物：

- `schema.ts`
- `types/save.ts`

讨论点：

- 世界状态第一版到底保留哪些字段。
- 美女、高手、普通 NPC 是否用同一 `NpcState` 扩展。

### M04 Action 与 Dispatcher

职责：

- 所有玩家操作统一变成 `GameAction`。
- UI、AI 叙述、事件监听都不能直接改存档。
- Dispatcher 先 tick，再校验 action，再调用 engine。

Action 初始分类：

- `GAME_INIT`
- `SAVE_SWITCH`
- `TIME_ADVANCE`
- `LOCATION_CHANGE`
- `COMMS_SEND`
- `NPC_GENERATE`
- `NPC_INTERACT`
- `BEAUTY_RECRUIT`
- `MASTER_RECRUIT`
- `COMBAT_START`
- `COMBAT_COMMAND`
- `COMBAT_END_APPLY`
- `CULTIVATION_START`
- `CULTIVATION_BREAKTHROUGH`
- `BUSINESS_BUILD`
- `BUSINESS_COLLECT`
- `QUEST_ACCEPT`
- `QUEST_COMPLETE`
- `TICK_NOW`

产物：

- `types/actions.ts`
- `engine/dispatcher.ts`

验收：

- 任意状态变化都能在 actionLog 中追溯来源。

### M05 Tick 与时间系统

职责：

- 统一推进世界时间、离线收益、任务冷却、经营收益、战斗行动条、NPC 行程。
- 设置离线结算上限，避免长时间关闭后一次性结算爆炸。

产物：

- `engine/tick.ts`
- `公式书/01_时间与tick.md`

讨论点：

- 游戏时间与现实时间的比例。
- 离线结算上限。
- 是否允许玩家手动等待/休息推进时间。

### M06 公式书系统

职责：

- 把所有可计算规则从提示词中剥离。
- 每条公式说明输入、输出、边界、取值范围、失败处理。
- 公式书先写文档，后续再落 TS 数据表或 engine 函数。

公式书分册：

- 时间与 tick。
- ATB 战斗。
- 养成与关系。
- 美女收集与培养。
- 高手收集与派遣。
- 经营收益。
- 任务奖励。
- 掉落与稀有度。
- NPC 生成约束。

验收：

- AI 提示词不承担数值公式。
- engine 可按公式书复现每个结果。

### M07 世界文本资源库与索引前置

职责：

- 参考澜景市，建立古风大世界文本资源库。
- `generateRaw()` 前置层只选择资源 ID。
- 脚本读取资源正文并按槽位组装给正文生成。
- 重 roll 时重新选择资源。

资源分组建议：

- `00_规则层`: 输出边界、AI 权限、格式强约束。
- `01_世界总纲`: 时代、地理、基础势力。
- `02_地域势力`: 区域、宗门、家族、商会、江湖组织。
- `03_地点设施`: 城镇、秘境、店铺、据点。
- `04_NPC与群像`: 已生成/固定 NPC 简档。
- `05_玩法规则`: 战斗、经营、收集、养成、任务。

产物：

- `services/resourceIndexService.ts`
- `services/resourceAssemblyService.ts`
- `文本资源库/index.yaml`
- `提示词/resource-selector.txt`

验收：

- 前置层输出只允许资源 ID + END。
- 正文层看不到检索过程。
- 资源缺失时脚本有兜底候选。

### M08 内置预设与提示词模块

职责：

- 将正文叙述、资源检索、NPC 生成、总结记忆拆成不同内置预设。
- 所有任务提示词放 `提示词/`，预设装配逻辑放 `内置预设/`。

预设类型：

- `narrator`: 正文叙述，只写可见剧情。
- `raw-selector`: 资源 ID 检索。
- `npc-generator`: 配角生成。
- `summary`: 大总结/角色记忆/动态人设。
- `cleanup`: 输出清洗或标签修复。

验收：

- 正文生成不能输出 JSON、MVU、存档补丁。
- Raw 任务默认静默，不写聊天记录，不改存档，除非服务层明确应用结果。

### M09 AI 生成服务

职责：

- 封装 `generate()` 和 `generateRaw()`。
- 正文生成接收权威局势摘要、资源组装包、玩家输入。
- 流式输出只作为显示层文本，不作为权威状态。
- AI 输出可被清洗、截取、记录为消息，但不能直接改主存档。

产物：

- `services/generateService.ts`
- `services/rawTaskService.ts`

验收：

- 正文回合能拿到脚本权威局势。
- 后台任务和正文任务互不污染。
- 生成失败不会破坏存档。

### M10 NPC / 配角生成系统

职责：

- 参考一键角色卡写卡器的生成、解析、校验、重试流水线。
- NPC 生成不是用户写卡，而是游戏运行时生成配角。
- 生成结果必须结构化入库，保证 NPC 后续一致。

生成流程：

1. 收集上下文：地点、势力、剧情原因、玩家已知信息、缺口类型。
2. 调用内置 NPC 生成预设。
3. 要求输出 `<content><npc_result>...</npc_result></content>`。
4. parser 提取字段。
5. 校验工程词、空字段、重复 ID、别名冲突。
6. 写入 `save.npcs`。
7. 更新文本资源索引，使之后能被资源路由选中。

字段建议：

- `npcId`
- `name`
- `aliases`
- `category`: beauty/master/common/enemy/merchant/faction_member
- `appearance`
- `personality`
- `motivation`
- `faction`
- `currentLocationId`
- `relationshipSeed`
- `scheduleHint`
- `interactionRules`
- `memorySeed`
- `tags`

明确不做：

- 不生成多阶段人设。
- 不让 AI 直接写世界书或主存档补丁。

### M11 记忆与智脑系统

职责：

- 从明月秋青 B4 转化为本项目长期记忆。
- 每隔一定事件/楼层/时间触发总结。
- 产出剧情摘要、NPC 记忆、动态人设、玩家行为模式。
- 注入时按在场 NPC、地点、任务、关系链筛选。

子模块：

- 正文捕获与剧情片段记录。
- 大总结。
- NPC 记忆库。
- 动态人设。
- 玩家行为模式。
- 神经链记忆激活。
- 旧记录压缩/隐藏策略。

产物：

- `services/memoryService.ts`
- `vendor/b4/` 裁剪副本
- `提示词/memory-summary.txt`

讨论点：

- 总结触发条件用“AI 回复数”、Action 数，还是游戏时间。
- 旧聊天楼层是否隐藏，或只在本项目消息日志中压缩。

### M12 ATB 战斗骨架

职责：

- 从 Unity_Airp 战斗模块抽取结构，转成 TypeScript。
- 删除境界硬锁和最高战力锁定。
- 保留 ATB、ReadyQueue、指令、效果、状态、日志、BattleResult。

第一版保留：

- `BattleSetup`
- `BattleUnitSnapshot`
- `BattleState`
- `BattleCommand`
- `BattleResult`
- `BattleEventLog`
- 行动条增长。
- 冷却与资源消耗。
- 伤害、治疗、护盾、状态、拉条、退条。
- 敌方基础 AI。

明确删除/改写：

- `RealmOutcomePolicy`
- `HighestPowerLock`
- `TrueImmortalOutcomeRule`
- `MethodRequirementGate` 中的境界门槛硬锁。

替代方案：

- `CombatRuleGate` 只检查单位存在、是否可行动、目标是否合法、资源是否足够、技能是否可用。

### M21 测试与验收

职责：

- 每个核心模块都有最小验收。

最小闭环验收：

- 玩家能打开脚本入口。
- 能新建/读取浏览器缓存存档。
- 能执行一个 Action。
- Dispatcher 能结算并写入存档。
- AI 能收到权威局势摘要并输出正文。
- 正文不改权威状态。
- 刷新后能继续游戏。

扩展验收：

- 资源前置检索可重 roll。
- NPC 生成可重复读取且一致。
- ATB 战斗能独立跑通。
- 美女招募流程能闭环。
- 经营收益能 tick 结算。
- 大总结能注入后续剧情。

## 4. 推荐讨论顺序

1. 存档系统：浏览器缓存、存档槽、schema 第一版。
2. Action/Dispatcher：先确定所有状态变化入口。
3. 公式书总纲：哪些结果必须脚本裁决。
4. 文本资源库与索引前置：古风大世界资源怎么分组。
5. 正文生成服务：AI 权限和注入结构。
6. NPC 生成流程：配角字段和一致性规则。
7. ATB 战斗骨架：保留哪些战斗机制，删哪些境界锁。
8. 美女收集/养成。
9. 高手收集/派遣。
10. 经营系统。
11. 记忆与智脑。
12. 临时前端接口。
13. 正式前端界面。
