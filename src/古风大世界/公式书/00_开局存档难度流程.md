# 00_开局存档难度流程

> 参考来源：`E:\Unity_Airp` 的开局、存档、难度选择系统。
> 本文件只吸收流程骨架和数据边界，不吸收 Unity UI 实现，不吸收难度数值细节。

## 1. 吸收范围

保留：
- 开局入口：玩家从“入世”进入游戏流程。
- 存档槽：固定 9 个槽位，`slotId` 为 1 到 9。
- 阶段恢复：根据 `gameStage` 判断继续游戏时回到哪一步。
- 难度分类：只保留 4 个分类 ID 和显示名，具体规则内容先空着。
- 存档摘要：用于存档列表展示的轻量信息。

不保留：
- Unity 的本地 JSON 文件路径。
- Unity UI 布局、动画、图片资源加载方式。
- 难度倍率、AI 偏置、掉落、NPC 态度等具体内容。
- Unity 的具体全局标记实现。

改写保留：
- 开场白跳过权限可以全局解锁：任意一个存档完整看完开场白后，其他存档也允许跳过。

## 2. 目标流程

本项目建议流程：

```text
BOOT
-> SAVE_SELECT
-> DIFFICULTY_SELECT
-> CHARACTER_CREATE
-> OPENING_PROLOGUE
-> WORLD_READY
```

与 Unity 原流程对应：

| 本项目阶段 | Unity 参考阶段 | 说明 |
| --- | --- | --- |
| `SAVE_SELECT` | 标题页“入世”后打开存档槽 | 先选槽，再决定新建或读取 |
| `DIFFICULTY_SELECT` | `DifficultySelection` | 新档默认进入难度选择 |
| `CHARACTER_CREATE` | `CharacterCreation` | 难度确定后创建角色 |
| `OPENING_PROLOGUE` | `OpeningPrologue` | 角色创建后进入开场白/加载层 |
| `WORLD_READY` | `WorldMap` | 后续大世界入口 |

## 3. 存档槽规则

固定 9 个槽位：

```ts
const SAVE_SLOT_COUNT = 9;
type SaveSlotId = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9;
```

每个槽位互相隔离：
- 玩家状态隔离。
- NPC 隔离。
- 背包、地图、关系、经营、战斗、记忆、日志隔离。
- 资源缓存可以全局共用，但必须带 `resourceVersion`，不能混进权威存档。

## 4. 浏览器缓存 key

Unity 使用本地文件：

```text
slot_01.json
slot_02.json
...
slot_09.json
```

本项目改为浏览器缓存：

```text
gufeng-world/save-index
gufeng-world/active-save-id
gufeng-world/save/{slotId}
gufeng-world/settings
gufeng-world/opening-prologue-skip-unlocked
gufeng-world/resource-cache/{resourceVersion}
```

建议：
- `localStorage` 放索引、当前槽位、轻量设置。
- `IndexedDB` 放大型存档、历史快照、长日志、资源缓存。
- 第一版可以先用统一存储接口封装，具体底层可后续替换。

## 5. 存档摘要

存档列表只读取摘要，不直接加载全量大存档。

建议字段：

```ts
interface SaveSlotSummary {

  schemaVersion: number;
  characterName: string;

  gameStageName: string;
  createdAt: string;
  savedAt: string;
  difficultyId: DifficultyId | '';

```

## 6. 权威存档第一层字段

第一版只定外壳，不填玩法细节：

```ts
interface GameSave {
  meta: {
    schemaVersion: number;
    slotId: SaveSlotId;
    createdAt: string;
    savedAt: string;
    contentVersion: string;
  };
  flow: {
    gameStage: OpeningGameStage;
  };
  opening: {
    difficultyId: DifficultyId | '';
    difficultyName: string;
    difficultyPayload: Record<string, never>;
    prologueCompleted: boolean;
  };
  player: {
    name: string;
    gender: string;
    avatarId: string;
    origin: string;
    spiritRoot: string;
    pathFocus: string;
    temperament: string;
  };
  world: Record<string, unknown>;
  npcs: Record<string, unknown>;
  logs: Record<string, unknown>;
}
```

说明：
- `difficultyPayload` 暂时必须为空对象。
- `prologueCompleted` 表示当前存档是否已经完成或跳过开场白。
- `opening-prologue-skip-unlocked` 是全局跳过权限：任意存档完整看完一次开场白后，其他存档也允许跳过。
- `world`、`npcs`、`logs` 先留壳，后续模块逐步细化。

## 7. 阶段枚举

```ts
type OpeningGameStage =
  | 'DIFFICULTY_SELECT'
  | 'CHARACTER_CREATE'
  | 'OPENING_PROLOGUE'
  | 'WORLD_READY';
```

恢复规则：
- 空槽：创建新存档，进入 `DIFFICULTY_SELECT`。
- `DIFFICULTY_SELECT`：回到难度选择。
- `CHARACTER_CREATE`：回到角色创建。
- `OPENING_PROLOGUE`：回到开场白/加载层。
- `WORLD_READY`：进入大世界接口层。
- 未知阶段：回退到 `DIFFICULTY_SELECT`，并记录恢复警告。

## 10. 酒馆边界预判

本模块在酒馆内应当只依赖：
- 浏览器本地存储能力。

## 12. 开局流程细化结论

### 12.1 返回规则

正式进入开场白之前，所有步骤都允许返回。

建议状态流：

```text
SAVE_SELECT
<-> DIFFICULTY_SELECT
<-> CHARACTER_CREATE
-> OPENING_PROLOGUE
-> WORLD_READY
```

规则：
- `DIFFICULTY_SELECT` 可以返回 `SAVE_SELECT`。
- `CHARACTER_CREATE` 可以返回 `DIFFICULTY_SELECT` 或 `SAVE_SELECT`。
- 点击“正式入世”后写入角色创建结果，并推进到 `OPENING_PROLOGUE`。
- 进入 `OPENING_PROLOGUE` 后不再允许回到难度或角色创建，只允许完成、跳过或刷新后恢复。
- `OPENING_PROLOGUE` 完成或跳过都等同于看完，推进到 `WORLD_READY`。

### 12.2 存档到底存什么

采用“静态原始数据 + 存档可变数据”的模式。

静态原始数据不进存档：
- 难度四分类定义。
- 固定世界人口名单。
- 固定地点、势力、物品、技能、公式、文本资源。
- 项目内置预设和提示词。

存档内保存当前槽位的全部可变状态：
- 玩家当前状态。
- 当前流程阶段。
- 已选择难度 ID。
- 固定 NPC 的当前状态变化，例如关系、位置、伤势、是否死亡、是否已结识。
- 运行时生成 NPC 的完整档案，因为它们不在静态原始数据中。
- 背包、任务、经营、战斗、记忆、日志等后续模块写入的槽内数据。

加载时组合：

```text
项目内置静态数据
+ 当前存档里的可变状态
= 当前游戏运行态
```

这和 Unity 游戏存档的思路一致：游戏安装包里已有的资料不重复保存，存档只记录这个玩家这个槽位变成了什么样。

### 12.3 存档操作规则

删除：
- 必须弹内置二次确认框。
- 删除当前激活槽后，清空 `active-save-id`，返回存档选择。
- 删除行为写入全局操作日志，但不保留被删除存档正文。

复制：
- 从一个已有槽复制到另一个槽。
- 如果目标槽已有存档，必须二次确认覆盖。
- 复制后重写目标槽的 `slotId` 和 `savedAt`。
- 复制结果写入源槽、目标槽或全局操作日志，具体以后实现时按日志结构定。

导入：
- 通过文件选择读取 JSON。
- 先在内存中解析、校验、迁移、修复预览。
- 用户确认后才写入目标槽。
- 如果目标槽已有存档，必须二次确认覆盖。
- 导入时重写目标槽的 `slotId` 和 `savedAt`。

导出：
- 从当前槽或指定槽生成 JSON 文件。
- 导出文件包含存档正文、schema 版本、导出时间和简单校验信息。
- 导出动作只写一条轻量日志，不把导出文件内容反存进缓存。

修复：
- 修复工作区只存在内存中，不放进浏览器缓存。
- 能修的范围：缺字段补默认值、旧版本迁移、阶段字段回退、摘要重建、静态数据 ID 重新对齐。
- 不能修的范围：JSON 完全损坏到无法解析、玩家手动删除了大量必要结构且无法推断。
- 修复预览确认后，才把修复结果写回指定槽。

### 12.4 浏览器缓存设计

可在酒馆运行的建议方案：

- `localStorage`：保存轻量索引、当前激活槽、全局开场白跳过权限、轻量设置。
- `IndexedDB`：保存 9 个槽位的存档正文、摘要快照和小型操作日志。
- 内存：导入、导出、修复过程中的临时大对象。

建议 key：

```text
gufeng-world/save-index
gufeng-world/active-save-id
gufeng-world/opening-prologue-skip-unlocked
gufeng-world/settings
gufeng-world/slot/{slotId}
```

注意：
- 浏览器缓存属于当前浏览器、当前酒馆访问地址和端口。
- 清理浏览器站点数据会清掉存档。
- 如果从 `localhost` 换到 `127.0.0.1`，或端口变化，浏览器可能视为不同来源，旧缓存不会自动出现。
- 因此第一版必须提供导出功能，作为手动备份入口。

### 12.7 酒馆可运行性

开局模块不接入 AI。

可依赖：
- Tavern Helper 脚本在浏览器 iframe 中运行。
- 浏览器 `localStorage`。
- 浏览器 `IndexedDB`。
- 浏览器文件导入能力。
- 浏览器 Blob 下载能力。
- zod 校验。
- 内置 Vue 弹窗或后续正式前端。

不依赖：
- `generate()`。
- `generateRaw()`。
- 酒馆世界书写入。
- 酒馆聊天楼层作为权威存档。

结论：可以在酒馆运行。主要风险不是能力不足，而是浏览器缓存可能被清理或因访问地址变化而隔离，所以导出/导入是必须功能。

### 12.8 日志

写轻量日志，不写大内容。

建议日志分两类：
- 全局操作日志：删除、导入、导出、修复失败、修复应用、缓存异常。
- 槽内系统日志：新建、复制进来、阶段推进、开场白完成或跳过。

日志只保留摘要：
- 时间。
- 操作类型。
- 槽位。
- 成功或失败。
- 简短原因。

不保存：
- 导入文件原文。
- 导出文件原文。
- 修复前的大型残档。
- 修复过程中的临时对象。
