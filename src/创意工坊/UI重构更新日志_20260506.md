- `readPanelSize` 加载历史 localStorage 存档时也强制修正高度，防止旧数据破坏比例
- 默认尺寸：`1060 × 795`；受影响文件：`types.ts`、`App.vue`

### 4.5 面板最小尺寸约束

确保所有 UI 元素（尤其是类型标签栏 6 个选项）在最小尺寸下完整显示：

| 常量 | 旧值 | 新值 | 理由 |
|------|------|------|------|
| `MIN_PANEL_W` | 420px | **860px** | 6 个 tab 按钮约需 829px，含 30px 余量 |
| `MIN_PANEL_H` | 320px | **645px** | 4:3 对应 860 × 3/4 |

- `ws-type-tabs-left` 移除 `overflow-x: auto` / `scrollbar-width`，改为 `flex-shrink: 0`，防止按钮被压缩
- 最小宽度计算依据：6 个 tab 按钮总宽 ~593px + 间距 60px + 右侧控件 190px + 容器 padding 46px = **~889px**

## 五、前后端握手协议（Backend API Contract）

### 5.1 现有接口（已有后端支持）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 用户名密码登录，返回 `{ token, user }` |
| GET | `/auth/me` | 获取当前用户信息 |
| POST | `/auth/logout` | 登出 |
| GET | `/auth/discord` | Discord 注册跳转 URL |
| GET | `/api/works` | 作品列表（支持 page / page_size / type / search / sort / tag） |
| GET | `/api/works/tags` | 所有标签列表 |
| GET | `/api/works/:id` | 单作品详情 |
| GET | `/api/works/:id/download` | 下载作品内容 |
| POST | `/api/works` | 上传新作品（FormData） |
| PUT | `/api/works/:id` | 修改作品 |
| DELETE | `/api/works/:id` | 删除作品 |
| POST | `/api/works/:id/like` | 点赞/取消点赞，返回 `{ liked, like_count }` |
| GET | `/api/my/works` | 我的作品列表 |

### 5.2 合集功能新增/修改的接口需求

#### ① GET /api/works/:id — 合集类型需返回 children 字段

当 `type === 'collection'` 时，响应体需额外包含：

```json
{
  "id": 9995,
  "type": "collection",
  "title": "Stitch 合集",
  "children": [
    {
      "id": 99951,
      "title": "如月绘里奈",
      "type": "persona",
      "char_name": "如月绘里奈",
      "description": "...",
      "tags": ["OC", "现代"],
      "cover_url": "https://...",
      "card_link": "",
      "file_type": "json",
      "content": "{ ... }",
      "like_count": 102,
      "liked": false,
      "download_count": 532,
      "author": { "username": "Stitch", "display_name": "Stitch", "avatar": "..." }
    }
  ]
}
```

#### ② POST /api/works — 上传合集时传递子作品 ID

合集上传 FormData 新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定 `"collection"` |
| `title` | string | 合集名称 |
| `description` | string | 合集简介 |
| `cover` | File | 封面图（已裁切为 16:9） |
| `child_ids` | string (JSON) | 子作品 ID 数组，如 `"[9991, 9992]"` |

> 合集不传 `content`、`tags`、`card_file`、`disclaimer_agreed`

#### ③ PUT /api/works/:id/children — 向现有合集追加作品（新接口）

```
PUT /api/works/9995/children
Authorization: Bearer <token>
Content-Type: application/json

{ "add_ids": [9993, 9994] }
```

响应：

```json
{ "message": "已添加 2 件作品", "children_count": 6 }
```

#### ④ GET /api/my/works — 返回当前用户所有作品

前端"选择作品加入合集"选择器的数据来源，需返回完整 `WorkItem[]`，包含 `cover_url`、`type`、`char_name` 等字段。

## 七、生产模式二次审查修复

以下问题在调试模式下表现正常但生产模式下完全失效，已全部修复：

| # | 问题 | 原因 | 修复 |
|---|------|------|------|
| 1 | 合集选择器为空（UploadView） | `myWorks` 生产模式返回 `[]` | 新增 `myWorksFromApi` 状态，`watch(form.type)` 切换到 collection 时自动调 `fetchMyWorks` |

| 4 | 可选作品列表为空 | `availableToAdd` 硬编码读 `debugWorks` | 生产模式从 `myWorksForAdd`（API 数据）过滤 |
| 5 | 点击"添加"不拉数据 | 无 API 调用 | `onToggleAddWorks` 首次展开自动 `fetchMyWorks` |

| 7 | api.ts 缺接口 | 无 `child_ids`、无追加接口 | 新增 `child_ids` 参数和 `addWorksToCollection` 函数 |
| 8 | authorName 硬编码 | `Debug_User` 而非变量 | 改为 `DEBUG_CURRENT_USER` |
| 9 | 合集文案过期 | "上传角色卡 PNG" | 更新为"上传封面并选择作品" |

## 九、移动端全面适配（2026-05-07）

### 9.1 弹窗体系重构
