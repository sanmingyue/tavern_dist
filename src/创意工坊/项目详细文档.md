# 创意工坊项目详细文档

更新时间：2026-05-07

## 一、当前原则

创意工坊分为两个端：

- 用户前端：运行在酒馆助手/酒馆脚本环境里，负责浏览、上传、下载、收藏、点赞、评论、查看个人记录。
- 后端与管理端：运行在服务器，负责真实数据、审核、追溯、日志、权限、删除/隐藏等管理能力。

本项目当前以后端为真实数据源。前端 UI 可以继续美化，但接口字段、权限边界、审核状态、日志追溯都以后端实现为准。

管理员在用户前端仍然按普通用户使用；所有管理权限只在后端管理页/API 内执行。

## 二、角色与权限

### 普通用户

- 必须登录后使用，没有非登录用户流程。
- 普通用户可以只下载，也可以上传作品成为作者。
- 作者只能管理自己的作品，绝不能对其他作者作品产生删除或修改权限。
- 作者删除作品时使用软删除：用户端不可见，但后端数据、下载记录、评论、日志仍保留，便于误删恢复和追溯。
- 作者可以更新自己的作品。已通过作品提交更新后进入新版本审核，旧公开版本继续保留下载、收藏、评论等数据。
- 作者可以隐藏自己作品下的评论，但不能永久删除评论。

### 管理员

- 管理员 ID 通过服务器环境变量 `ADMIN_DISCORD_IDS` 配置，填写 Discord 用户 ID。
- 管理员拥有审核、驳回、隐藏、恢复、后端删除等权限。
- 管理员每一步操作都必须记录操作者、理由、时间戳和目标对象。
- 管理员的管理行为同样受日志追溯监管。

## 三、作品数据模型

作品基础字段：

- `id`：作品 ID。
- `user_id`：作者用户 ID。
- `title`：作品标题。
- `char_name`：角色名。人设/OC 与角色卡二创必须填写。
- `description`：简介。
- `type`：作品类型。
- `content`：作品内容。合集类型不直接存子作品内容。
- `tags`：标签数组。
- `cover_filename`：封面文件名。
- `card_link`：角色卡二创关联链接。
- `file_type`：内容文件类型。
- `status`：审核状态，包含 `pending`、`approved`、`rejected`。
- `visibility`：可见性，包含公开、管理员隐藏、作者软删除等状态。
- `download_count`、`like_count`、`favorite_count`、`comment_count`：统计数据。
- `created_at`、`updated_at`、`reviewed_at`：精准 ISO 时间戳。

作品版本字段：

- 作品更新会写入 `work_versions`。
- 已通过作品的新版本进入审核，不覆盖旧公开版本。
- 审核通过后，当前版本才更新到公开作品。
- 审核驳回时记录驳回理由，保留历史版本。

## 四、作者合集

合集不再上传角色卡 PNG，也不再用免责声明占位。

合集上传规则：

- 必须上传封面。
- 必须选择至少一个自己的作品。
- 只能选择自己已审核通过、公开、非合集的作品。
- 后端用 `collection_items` 保存合集与子作品关系。
- 单个合集最多添加 200 个子作品。

合集详情：

- 后端返回 `children` 子作品列表。
- 子作品只返回预览内容，不把完整下载内容直接暴露在合集详情里。
- 下载/导入子作品仍然走 `/api/works/:id/download`，保证下载日志与密钥追踪生效。

作者可以给自己的合集追加作品：

- 接口：`PUT /api/works/:id/children`
- 参数：`add_ids`
- 后端再次校验作者身份、作品归属、状态和可见性。

## 五、评论、收藏、点赞、下载

评论：

- 作品详情可以查看评论区。
- 登录用户可以发表评论。
- 用户可以删除/隐藏自己的评论。
- 作者可以隐藏自己作品下的评论。
- 管理员拥有最终处理权。
- 评论数量写入作品统计。

收藏：

- 作品支持收藏/取消收藏。
- 个人页可查看自己的收藏记录。
- 收藏记录包含作品标题、角色名、类型、封面、作者、收藏时间等。

点赞：

- 作品支持点赞/取消点赞。
- 点赞数量写入作品统计。

下载：

- 下载会记录用户、作品、时间、IP/User-Agent 等追溯信息。
- 个人页可查看历史下载记录。
- 历史下载记录只记录下载过哪些内容，不保存用户下载文件副本。

## 六、日志与追溯

所有关键操作都需要记录审计日志：

- 注册、登录、登出。
- 上传作品、更新作品、作者删除作品。
- 下载、点赞、收藏、评论。
- 密码创建与修改。
- 管理员审核、驳回、隐藏、恢复、删除。
- 管理员查看敏感信息。

日志要求：

- 日志内容使用中文字段，便于直接人工审查。
- 时间戳必须精确到 ISO 时间。
- 日志按天、按用户维度可检索。
- 管理端支持搜索、筛选与下载日志。
- 管理员操作也必须进入日志，不存在“无痕管理”。

## 七、密码查看

后端记录用户注册/修改时的密码明文快照，供管理员在必要时手动查阅。

注意：

- 密码不在列表中直接显示。
- 管理员需要进入具体查看动作。
- 查看动作本身写入审计日志。
- 早期注册、功能上线前没有记录明文密码的用户，无法从哈希反推出原密码，只能让用户重新修改密码后产生新记录。

## 八、前端对接状态

2026-05-07 已完成一次以后端为准的前端补全：

- `WorkshopView.vue` 对接真实合集子作品、收藏、评论、下载/导入。
- `ProfileView.vue` 增加历史下载和我的收藏。
- `MyWorksView.vue` 增加作者更新作品流程。
- `api.ts` 增加收藏、评论、个人下载、个人收藏、作品更新接口。
- `types.ts` 补全 `char_name`、合集子作品、评论、下载记录、收藏记录等类型。

后续前端美化可以继续在当前 UI 风格上做，但不要改变后端权限边界。

## 九、未来二传追踪第二层密钥

当前后端已经有下载记录与 `fingerprint_token`，可以追踪用户何时下载了哪个作品。

未来需要增加第二层“不好查的密钥”：

- 每次下载生成不可预测的用户级密钥。
- 文本类内容把密钥嵌入到不影响使用的隐藏标记或结构字段中。
- JSON 类内容优先写入不影响解析的元数据字段。
- PNG/角色卡类内容未来可考虑写入 PNG metadata 或下载包内的隐写标记。
- 后端保存密钥、用户、作品、下载时间、文件类型、版本号的映射。
- 管理端提供密钥反查入口，输入密钥后可定位下载用户与对应作品。

此功能需要单独设计兼容策略，避免破坏酒馆导入、世界书解析、正则规则和角色卡格式。

## 十、部署与验证

后端每次变更需要：

- 执行 `npm run build`。
- 本地临时数据库跑一次迁移/基础功能测试。
- 推送到服务器仓库主分支。
- 部署完成后检查 `/health`。

前端每次变更需要：

- 执行 `npm run build`。
- 确认 `dist/创意工坊/index.js` 与 sourcemap 已更新。
- 在酒馆环境中做一次登录、列表、详情、下载、收藏、评论、个人页、作者更新的人工回归。
