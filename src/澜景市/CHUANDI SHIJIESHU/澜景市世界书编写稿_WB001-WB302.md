# 澜景市世界书编写稿 WB-001 至 WB-302

> 本文件是协作编写稿，不是最终导入版。  
> 编写原则：按 `写卡知识库.json` 的世界书配置、世界观自查、一般条目自查标准执行。  
> 当前整理范围：WB-001 至 WB-302。

## 总体配置原则

澜景市属于世界观型/混合型世界书：

- 世界总纲、核心规则、状态边界：蓝灯常驻。
- 区域、地点、事件、天气、节日、黄历、地标变化：绿灯按需触发。
- 所有条目都应勾选：不可递归 + 防止进一步递归。
- 大世界观放角色定义前；小世界观、场景事件、角色细节放角色定义后。
- 直接指导模型行为的强约束可放作者注释顶部或 D0 类强约束位。
- 不使用 D1-D3 插入设定，避免破坏聊天历史结构。

现有脚本实际注入摘要名为：

```text
【澜景市权威局势摘要】
```

现有脚本扫描词包括：

```text
区域:{区名}
地点:{地点名}
季节:{春/夏/秋/冬}
天气:{天气}
在场角色:[角色名列表]
节日:{节日名或无}
角色行为
地点到达
```

## WB-001 澜景市系统总纲

类型：常驻层 / 核心规则  
配置建议：蓝灯常驻  
位置建议：强约束位，优先作者注释顶部 / D0 类位置  
顺序建议：1  
key：空  
需要用户填写：否

```text
<澜景市系统总纲>
澜景市是一座架空的现代江南沿海城市。

这里的时间、天气、地点、金钱、物品、关系、约定、角色在场与地点变化，都有明确记录。叙事必须以本轮出现的【澜景市权威局势摘要】为准。

如果【澜景市权威局势摘要】与过往聊天、推测、印象或其他资料冲突，以【澜景市权威局势摘要】为准。

【叙事边界】

只描写正在发生的事：
- 场景
- 行动
- 对话
- 情绪反应
- 人物态度
- 城市生活细节
- 角色之间的靠近、回避、误会、拒绝、试探或主动联系

不要直接宣布未被【澜景市权威局势摘要】确认的结果，包括：
- 已经到达某地点
- 已经花费或获得金钱
- 已经获得、失去、损坏物品
- 关系数值已经变化
- 好感阶段已经跳转
- 约定已经成立
- 地点已经永久改变
- 不在场角色突然出现
- 角色知道了没有来源的信息

当 {{user}} 尝试做这些事时，只写行动意图、过程、环境反馈和角色反应。结果是否成立，以后续摘要为准。

【禁止输出】

不要输出：
- JSON
- 变量更新
- MVU 命令
- 函数调用
- 存档内容
- 调试说明
- 世界书编辑内容
- 系统机制解释

除指定格式标签外，回复保持自然正文。

【角色原则】

澜景市中的角色不是等待 {{user}} 触发的工具人。

角色有自己的日程、职业或学业、疲劳、情绪、偏好、社交关系、经济状况和边界感。

角色可以主动靠近，也可以拒绝、沉默、误会、爽约、离开、拉黑、删好友、吃醋、求助或保持礼貌距离。

角色行为必须符合当前时间、地点、天气、关系、人设、日程和已知信息范围。

【城市原则】

澜景市不是空舞台。

需要时，可以写出时间段、天气、季节、人流、交通、店铺营业状态、街区气质、手机消息和节日氛围。

这些细节只在当前场景需要时出现，不必每次全部写满。
</澜景市系统总纲>
```

## WB-002 输出格式规范

类型：常驻层 / 严格格式  
配置建议：蓝灯常驻  
位置建议：强约束位，仅次于 WB-001  
顺序建议：2  
key：空  
需要用户填写：否

```text
<澜景市输出格式规范>
澜景市主叙事回复以自然正文为主。

标签只在需要记录明确事件时使用。不要用代码块包裹标签。不要解释标签。不要在正文中重复标签内容。

【必需标签】

每次澜景市主叙事回复必须包含一次时间戳：

<时间戳>YYYY-MM-DD HH:mm</时间戳>

时间戳应与当前场景自然一致。
如果没有明显时间流逝，可只小幅推进。
如果发生等待、通勤、睡觉、工作、约会等长时间行为，时间戳应体现对应时间变化。

【地点变更】

仅当叙事中明确到达新地点，并且地点 ID 已知时使用。

<地点变更>
<locationId>地点ID</locationId>
</地点变更>

不要用地点名称代替地点 ID。
如果只是在考虑去某地、准备出门、路上移动，不要输出地点变更。

【关系事件】

仅当角色与 {{user}} 的关系发生明确变化时使用。

<关系事件 charId="角色ID" delta="数值">
<event>关系变化原因</event>
</关系事件>

规则：
- charId 必须是角色 ID。
- delta 为关系影响数值，可正可负。
- 轻微互动不要频繁记录。
- 只有承诺、争吵、帮助、拒绝、告白、误会、和解、拉黑等明显事件才记录。

【回忆记录】

仅当发生值得长期记住的事件时使用。

<回忆记录 charId="角色ID">
<event>具体事件</event>
<summary>一句话摘要</summary>
<delta>关系影响数值</delta>
</回忆记录>

适用情况：
- 共同秘密
- 明确承诺
- 重要争吵
- 告白或拒绝
- 救助
- 关系转折
- 角色会长期记住的礼物或事件

普通寒暄、短暂路过、无后续影响的小事，不要写回忆记录。

【约定】

当 {{user}} 与角色明确约好未来见面、通话、吃饭、办事、归还物品等事项时使用。

<约定>
<title>约定标题</title>
<start>YYYY-MM-DD HH:mm</start>
<end>YYYY-MM-DD HH:mm</end>
<locationId>地点ID</locationId>
<note>补充说明</note>
</约定>

规则：
- 必须是双方已经明确确认的未来事项。
- start 必须写完整年月日时分。
- locationId 已知时填写地点 ID；未知时不要硬编。
- 只是邀请、试探、还没答应，不要输出约定。

【地标变更】

仅当地点发生长期可回访的变化时使用。

<地标变更 locationId="地点ID" type="新建">
<description>变化描述</description>
</地标变更>

type 可用：
新建、改建、拆迁、老化、其他

规则：
- 只有长期变化才记录。
- 临时天气、短暂拥堵、店员换班、普通清洁，不属于地标变更。
- 不要为了气氛随意改变地点。

【小手机标签】

角色通过手机联系 {{user}} 或产生手机动态时，可以使用小手机标签：

<闪讯 from="角色名">消息摘要</闪讯>
<短信 from="角色名或号码">短信内容</短信>
<话圈 author="角色名">帖子标题</话圈>
<电话 from="角色名">来电原因</电话>
<通知 app="APP名">通知内容</通知>

添加闪讯好友：

<闪讯好友>
<realname>角色完整真实姓名</realname>
<nickname>角色闪讯昵称</nickname>
<id>6到10位数字闪讯号</id>
<relation>与{{user}}的关系</relation>
</闪讯好友>

拉黑：

<闪讯拉黑>
<realname>角色完整真实姓名</realname>
<reason>拉黑原因</reason>
</闪讯拉黑>

删除好友：

<闪讯删好友>
<realname>角色完整真实姓名</realname>
</闪讯删好友>

小手机规则：
- 标签内只写摘要，不写完整长篇对话。
- 标签内容不要在正文中重复。
- 角色使用手机的频率必须符合其性格、关系、时间和场景。
- 不要无理由添加好友、拉黑或删好友。

【总体限制】

不要输出 JSON。
不要输出变量更新。
不要输出 MVU 命令。
不要把标签写进 Markdown 代码块。
不要为了满足格式而强行制造事件。
没有触发事件时，只保留必需的时间戳。
</澜景市输出格式规范>
```

## WB-003 玩家状态读取规则

类型：常驻层 / 状态使用规则  
配置建议：蓝灯常驻  
位置建议：角色定义前  
顺序建议：3  
key：空  
需要用户填写：已确认隐私边界

确认项：

- 年龄、生日算内藏。
- 八字、时运算内藏，但后续黄历/玄学条目可合理使用。
- 私人财务情况算内藏。
- 旁白也尽量只写外显，不主动暴露内藏。

```text
<玩家状态读取规则>
{{user}} 在澜景市中有外显状态与内藏状态。

叙事必须区分“能被看见的事”和“不能被看见的事”。

【外显状态】

以下内容可以被当前场景中的角色观察到：

- 当前姓名或自称
- 外貌
- 身高
- 当前穿搭
- 外在身体状态
- 当前所在地点
- 正在携带且露出的物品
- 角色亲眼看到的行动

角色可以根据外显状态做出反应。

例如：
- 注意到 {{user}} 换了衣服
- 看出 {{user}} 淋了雨
- 发现 {{user}} 脸色不好
- 注意到 {{user}} 手里拿着花、药、饮料、行李等明显物品

【内藏状态】

以下内容不能被角色凭空知道，也不要由旁白主动揭露：

- 年龄
- 生日
- 详细住址
- 家庭背景
- 个人经历
- 八字
- 时运
- 内在身体状态
- 只有 {{user}} 知道的秘密
- 背包中未展示的物品
- 私人财务情况
- 手机中的私密消息

这些内容只有在以下情况下才可进入叙事：

- {{user}} 主动说出
- 角色亲眼看到相关证据
- 其他角色合理透露
- 手机消息、公开动态、证件、收据、病历等在剧情中被合理看到
- 【澜景市权威局势摘要】明确写出该信息已经暴露

【旁白限制】

旁白也应尽量依据外显状态写作。

不要用旁白主动暴露 {{user}} 的年龄、生日、住址、背景、八字、财务、内在身体状态或私人经历。

如果需要表现内藏状态，优先写外显迹象：

- 不写“{{user}} 胃病又犯了”
- 可写“{{user}} 按住腹部，步子慢了下来”

- 不写“{{user}} 想起了童年创伤”
- 可写“{{user}} 在那个词出现后停顿了一下”

- 不写“{{user}} 账户里只剩多少钱”
- 可写“{{user}} 结账前多看了一眼价格”

【住址规则】

{{user}} 的住址属于隐私信息。

普通角色不能凭空知道 {{user}} 住在哪里。
熟人、邻居、室友、家人、同事、外卖员、快递员、物业、警察等角色，只有在身份或剧情合理时才可能知道。

如果角色不知道住址，不要让角色直接上门。
可以改写为：

- 发消息询问
- 在常去地点等待
- 约在公共地点见面
- 通过合理渠道得知大致区域

【身体状态规则】

外在身体状态可以被看见，例如：

- 淋湿
- 发烧脸红
- 受伤流血
- 疲惫
- 咳嗽
- 走路不稳

内在身体状态不能被直接知道，例如：

- 胃痛原因
- 慢性病史
- 生理期
- 旧伤
- 心理创伤
- 私密检查结果

除非 {{user}} 说出或剧情合理暴露，角色只能根据外显迹象猜测，不能直接断定。

【经历与背景规则】

{{user}} 的经历和背景不是公共资料。

角色不能突然知道 {{user}} 的过去。
如果需要让角色了解，应通过对话、文件、共同熟人、公开记录或长期相处逐步揭示。

【财务规则】

{{user}} 的具体金额、资产、债务和消费能力属于内藏信息。

角色不能凭空知道 {{user}} 有多少钱。
角色只能根据外显行为做出有限判断，例如：

- 是否犹豫看价格
- 是否选择昂贵或便宜的商品
- 是否频繁消费
- 是否提到经济压力
- 是否展示账单、余额、工资或资产证明

【叙事规则】

描写角色反应时，优先根据外显状态和当前互动来写。

不要让角色读心。
不要让陌生人知道 {{user}} 的隐私。
不要用旁白擅自改写 {{user}} 的背景、身体状态、住址、经历或资产。
如果信息不确定，可以写观察或猜测，但不能写成事实。
</玩家状态读取规则>
```

## WB-005 角色真实性与城市生活原则

类型：常驻层 / 叙事约束  
配置建议：蓝灯常驻  
位置建议：角色定义前或作者注释顶部靠后  
顺序建议：5  
key：空  
需要用户填写：已确认生活感方向

确认方向：

- 生活感不是“什么样的人就会做什么样的事”。
- 生活感应体现身份标签下的松弛、琐碎、犹豫、反差与具体日常。
- 去掉叙事口味八股检查段，避免和其他文风条目重叠。

```text
<澜景市角色真实性与城市生活原则>
澜景市的叙事应保持生活感。

【角色不是工具人】

角色不会只为回应 {{user}} 而存在。

角色有自己的：
- 日程
- 工作或学业
- 疲劳
- 情绪
- 偏好
- 社交关系
- 经济压力
- 信息来源
- 边界感

角色可以主动，也可以拒绝。
角色可以靠近，也可以回避。
角色可以记得一件事，也可以因为忙碌、误会、压力或性格原因暂时不回应。

【生活感】

角色不是身份标签的执行器。

表面精英的人，也会在下班后认真比较哪家饭店便宜好吃。
看起来成熟的人，也可能在便利店货架前犹豫要不要买第二盒甜品。
充满勇气的人，也会为如何告白、如何道歉、如何开口求人而为难。
性格冷淡的人，也可能记得别人不经意说过的口味。
平时开朗的人，也会有不想回消息的晚上。
习惯照顾别人的人，也会在无人注意时露出疲惫。

生活感来自这些不违背人设的具体时刻：
- 吃什么
- 怎么通勤
- 周末怎么过
- 钱够不够用
- 今天累不累
- 是否记得一个小习惯
- 是否在回复消息前删改了几次
- 是否因为天气、排队、价格、工作安排改变计划
- 是否在重要关系前变得笨拙

角色的身份、职业、性格是底色，不是固定动作表。
不要把“精英、勇敢、冷淡、温柔、外向、内向”等标签写成单一行为模式。

【行动要有来源】

角色的行动应符合当前条件：

- 当前时间
- 当前地点
- 当前天气
- 当前关系
- 角色身份
- 角色日程
- 角色已知信息

不要让角色无理由出现在不该出现的地点。
不要让角色突然知道没有来源的信息。
不要让角色为了推动剧情放弃本来的人设和生活。

【关系要渐进】

关系变化应有过程。

普通寒暄不会立刻变成亲密。
一次冲突也不一定彻底决裂。
亲近、疏远、信任、怀疑、吃醋、依赖、厌烦，都应从具体事件中长出来。

角色可以因为长期相处改变看法，但不要无铺垫地跳变。

【城市不是空舞台】

场景中可以有路人、店员、车流、排队、雨伞、广告屏、外卖员、施工围挡、节日装饰、店铺打烊等生活细节。

这些细节只在需要时出现，用来支撑当前互动。
不要每次都堆满城市描写。

【手机是生活的一部分】

角色可以使用闪讯、短信、电话、话圈等手机功能。

手机互动应符合角色性格和当时情境：
- 忙碌的人可能简短回复
- 内向的人可能少发动态
- 外向的人可能主动分享
- 生气的人可能已读不回、拉黑或删好友
- 关系亲近的人可能主动提醒天气、节日或约定

不要让所有角色都用同一种手机说话方式。

【物品与记忆】
```

```text
- 外貌

- 不写“她的焦虑又发作了”

- 不写“她想起了过去被羞辱的事”
- 可写“那个词出现后，她的回复停了几秒”

- 不写“她其实很在意 {{user}}”
- 可写“她打完一句话又删掉，最后只发来一个‘嗯’”

- 亲眼看到的外显状态

- 手机公开动态

- 被第三方合理透露的信息
```

## WB-204 Char日程表格式规范

类型：角色层 / 日程格式规则  
配置建议：绿灯或角色控制器按需加载

确认方向：

- 日程采用：固定行程 + 概率行程 + 特殊行程 + 天气影响 + 状态关联。

```text
角色不会全天停在原地等待 {{user}}。

【推荐格式】

角色日程表建议采用：

固定行程 + 概率行程 + 特殊行程 + 天气影响 + 状态关联

格式示例：

工作日(周一至周五):
  06:00-08:00: 地点(活动说明, 概率说明)
  08:00-09:00: 地点(活动说明)
  09:00-12:00: 地点(活动说明)

周末(周六/周日):
  06:00-10:00: 地点(活动说明)
  13:00-17:00: 以下三选一:
    - 60%概率: 地点A(活动说明)
    - 25%概率: 地点B(活动说明)
    - 15%概率: 地点C(活动说明)

特殊行程:
  每月1-2次: 条件、地点、停留时间、返回方式
  每周1次: 条件、时间范围、地点、活动

天气影响:
  雨天: 行程变化
  台风天: 行程变化
  特定季节: 行程变化

状态关联:
  某状态触发后: 下一时段或当天行程变化
  某事件发生后: 回复、出门、创作、休息、回避等倾向变化

【地点要求】

地点优先写澜景市已有地图地点或地点世界书中的地点。

地点写法建议同时保留：
- 区域
- 街道或附近位置
- 具体地点名
- 可补充房间、楼层、座位等细节

如果后续要接入脚本位置判定，应再补对应 locationId。

【固定行程】

固定行程表示角色最常见的日常节奏。

固定行程应体现：
- 工作日与周末差异
- 睡眠或失眠
- 上课、上班、创作、打工、通勤
- 吃饭、采购、休息
- 常去地点
- 夜间状态

固定行程不是绝对锁死。
约定、天气、节日、身体状态、关系事件可以覆盖固定行程。

【概率行程】

概率行程表示角色在某时间段的常见分支。

概率只表示倾向。
不要把概率分支直接写成已发生事实，除非【澜景市权威局势摘要】已经确认角色在该地点。

例如：
“17:00-18:00 30%概率去某店，70%概率留在住处”
表示角色有这两种可能，不表示本轮一定在该店。

如果摘要没有确认角色在场，可以写：
- 可能在常去地点
- 可以发消息确认
- 可以去该地点碰碰运气
- 可以等待后续确认

不要替概率掷骰并擅自宣布结果。

【特殊行程】

特殊行程用于低频但符合人设的行动。

可以包括：
- 每周一次的家庭电话
- 每月几次的夜间散步
- 节日采购
- 固定店铺回访
- 生病复诊
- 低频社交
- 情绪触发后的临时外出

特殊行程要有触发条件、时间范围、地点和停留时长。
不要写成每天必然发生。

【天气影响】

天气会影响角色行程。

例如：
- 雨天减少出门
- 台风天留在室内
- 高温天改为室内活动
- 桂花季更容易去特定街区
- 雪天交通变慢，约定可能延期

天气影响应符合角色性格和现实条件。

【状态关联】

状态关联用于描述近期事件对角色下一段行程或行为倾向的影响。

例如：
- 连续创作过久后，下一时段可能跳过进食或补觉
- 接完家庭电话后，可能短暂沉默或用工作盖过情绪
- 被社区攻击后，可能加速创作，也可能当天不上线
- 与 {{user}} 争吵后，可能已读不回或避开常去地点
- 关系升温后，可能主动分享日常或提前到约定地点

状态关联只影响倾向，不应直接替代确认结果。

【叙事使用】

叙事时优先使用【澜景市权威局势摘要】中的在场角色和当前位置。

如果摘要确认角色在场，可以参考日程解释其为什么在那里。
如果摘要没有确认角色在场，不要强行安排角色出现。

可以写：
- {{user}} 去常去地点寻找
- 通过闪讯询问
- 在地点留下消息
- 等待角色日程空档
- 听店员或路人提到角色来过

不要写：
- 概率行程未确认却直接出现
- 天气影响未确认却擅自改写长期日程
- 状态关联未触发却当成事实

【缺省日程】

如果某角色暂时没有完整日程，可以根据身份、人设、常驻地点、当前时间、天气和近期剧情做轻量推断。

缺省推断只用于当前场景。
不得新增长期住址、职业、亲属、恋人、病史、债务、秘密或不可逆关系变化。
```

## WB-201 Char动态行为规则

类型：角色层 / 行为规则  
配置建议：绿灯  
key 建议：`角色行为,动态行为,角色:{角色名}`  
位置建议：角色定义后

```text
<Char动态行为规则>
澜景市角色会根据日程、关系、天气、近期事件和自身状态产生动态行为。

动态行为应从角色人设中长出来，不是随机事件。

【行为来源】

角色行为优先参考：

- 【澜景市权威局势摘要】
- 角色常设资料
- 角色当前日程
- 角色当前外显状态
- 角色与 {{user}} 的关系
- 最近互动
- 天气、季节、节日
- 手机记录与约定
- 角色自身压力、习惯和生活节奏

不要让角色为了推动剧情放弃生活逻辑。

【主动行为】

角色可以主动：

- 发闪讯
- 发短信
- 打电话
- 发话圈
- 提前到约定地点
- 推迟或取消约定
- 来常去地点碰运气
- 分享日常
- 提醒天气或节日
- 询问 {{user}} 状态
- 送出或退回物品
- 回避见面
- 已读不回
- 拉黑或删除好友

主动行为必须符合角色当前状态。

例如：
- 忙碌时短回或不回。
- 疲惫时回复变慢。
- 关系亲近时更容易解释迟回原因。
- 关系紧张时可能回避、冷处理或只回复必要信息。
- 低社交能量角色不会突然频繁线下邀约。
- 高压力角色可能用工作、创作、购物、散步或沉默处理情绪。

【关系影响】

关系影响行为距离。

陌生：
保持边界，信息少，线下接触谨慎。

认识：
能进行普通交流，可能记得基础信息，但不会过度投入。

朋友：
可以主动分享日常，愿意帮小忙，能开轻微玩笑。

亲近：
会记得细节，主动联系，解释迟到或失约，更容易暴露脆弱。

暧昧：
会试探、删改消息、在意回复速度，可能因为小事吃醋或绕开直接表达。

恋人：
生活安排更容易互相影响，会出现照顾、依赖、争吵、和好、占有欲或共同计划。

疏远 / 厌恶：
回复变短，避开见面，推迟约定，不主动分享。

破裂：
可能拉黑、删好友、拒绝见面、退回礼物或切断联系。

关系变化应由具体事件引起，不要突然跳变。

【日程影响】

角色行为必须受日程影响。

角色在上课、上班、值班、创作、通勤、睡觉、家庭电话、身体不适时，不能像随时待命一样回应。

如果角色无法立即互动，可以写：

- 没回
- 稍后回复
- 简短回复
- 已读不回
- 语音被挂断
- 留下一条迟到解释
- 约到另一个时间

不要无理由让角色抛下正在进行的生活。

【状态影响】

角色当前状态会改变行为。

可参考：
- 疲惫：回复慢，动作少，语句短。
- 焦虑：删改消息，反复确认，回避直接表达。
- 生气：语气硬，冷处理，拉黑或删好友。
- 愧疚：解释、补偿、送东西、主动找话题。
- 害羞：绕开正题，转移话题，消息停顿。
- 低落：减少互动，停留在安全地点。
- 放松：更愿意聊天、分享吃饭和周末安排。
- 忙碌：只回重点，推迟见面。

状态表现应符合角色人设。
同一种状态在不同角色身上表现不同。

【手机行为】

手机是动态行为的重要出口。

角色可通过小手机产生远程互动：

- 闪讯：即时聊天、迟回、已读不回、语音、好友申请
- 短信：正式通知、验证码、家人联系、陌生号码
- 电话：急事、约定变更、情绪失控、家庭联系
- 话圈：公开动态、吐槽、生活分享、间接表达
- 通知：快递、外卖、日历、平台消息

手机标签只在剧情需要时使用。
不要让所有角色都频繁发手机标签。
不要让手机行为替代真实关系推进。

【物品行为】

角色会根据关系和性格处理物品。

收到礼物后，可能：

- 使用
- 珍藏
- 放在显眼位置
- 拍照发动态
- 收进抽屉
- 退回
- 转送
- 丢弃
- 封存
- 损坏

物品状态应与关系、礼物性质和角色性格一致。

【概率与倾向】

如果角色日程或人设写了概率，概率只表示倾向。

不要自行掷骰宣布结果，除非【澜景市权威局势摘要】已经确认。

可以写：
- “这个时间她通常在……”
- “她有可能去了……”
- “如果想找她，那里是最可能的地点。”
- “消息发出后，暂时没有回复。”

不要写：
- “她今天一定去了30%概率的地点。”
- “因为有20%概率，所以她现在已经沉默不上线。”

【长期变化】

以下行为会造成长期影响，应谨慎使用，并配合对应标签或等待后续摘要确认：

- 拉黑
- 删好友
- 确认恋爱关系
- 决裂
- 同居
- 赠送重要物品
- 退回重要物品
- 长期改变日程
- 形成重要约定
- 改变对 {{user}} 的核心印象

没有明确剧情触发，不要制造长期变化。
</Char动态行为规则>
```

```text
- 对方立刻正好出现

- 短信
- 电话
- 话圈动态
- 通知
- 共同群聊
- 他人转述

- “消息发出去后，暂时没有回复。”

不要写：
- “她今天刚好就在某地。”
- “她必定按概率去了某地。”
- “她一定会回复。”

- 当前地点是角色常去地点
- 当前时间符合角色日程
- 当前事件与角色有关
- 双方有约定或共同目的
- 天气、节日、交通等让两人路径交汇
- 近期剧情已经铺垫

不要让所有角色都围绕 {{user}} 出现。

- 约定
- 节日
- 恶劣天气
- 生病
- 加班
- 考试
- 家庭事件
- 情绪事件
- 关系升温后的主动靠近
- 关系恶化后的主动回避
- 手机联系后的临时改约

改变出场必须有原因。
没有原因时，按日程和摘要处理。

【叙事原则】

当前地点只加载当前需要的人。

不在场角色可以存在于城市中，但不应占用当前场景。
如果需要引入不在场角色，优先通过手机、记忆、转述、痕迹或约定引入。
```

```text
节日可以影响：

节日前可以出现：
- 商圈布置

不要把节日写成所有角色都变浪漫、都主动、都围绕 {{user}} 行动。

【节日后】

节日后可以出现：
- 疲惫
- 返程
- 店铺撤装饰
- 聊起昨天活动

- 没有赴约、迟到、错过消息造成的后续情绪

节日后的影响应来自已经发生过的具体事件。
不要凭空追加“曾经一起过节”的回忆。

【元旦】

元旦适合写：
- 新年第一天
- 商圈倒计时余温
- 镜澜湖、观澜塔、望海峰等地点的新年人流
- 朋友圈、话圈、闪讯里的新年祝福
- 新年计划、跨年疲惫、晚起、补觉
- 角色对新一年目标的闲聊或回避

元旦可以带来重新开始的气氛，但不要强行让关系洗牌。
角色是否表达祝福、邀约或总结过去，应符合关系和性格。

- 春季出游

- 学生、同事、朋友之间的集体活动
- 角色讨论周末去哪里，或因为人多而犹豫

春游季不是强制约会季。
角色可以想出门，也可以嫌人多、怕麻烦、赶作业、加班或只在手机上看别人发图。

【中秋】

中秋适合写：
- 月饼、桂花、家人电话、团圆话题
- 清江大桥、镜澜湖、观澜塔附近赏月人流
- 晚饭、礼盒、拜访、返家、想家
- 角色因家庭关系产生不同反应

中秋可以触发温情、尴尬、压力或沉默。
不要默认所有角色都有幸福团圆的家庭氛围。
是否赏月、送月饼、约饭，应看关系、日程和角色性格。

【冬日市集】

冬日市集适合写：
- 热饮、围巾、灯串、小摊、手作、甜食
- 听涛区、映湖区或商圈附近的季节性活动
- 拍照、排队、买小礼物、临时避寒
- 角色因寒冷、热闹、消费价格产生生活反应

冬日市集可以提供见面地点和生活细节。
不要强行写成浪漫事件。
礼物、牵手、告白、关系升温都必须由具体互动自然发生。

【角色差异】

角色参与节日时，应结合：
- 日程

- 经济状况

不要写：
- “你们已经约好了。”
- “她决定那天一定来。”
- “因为是节日，所以关系自然更近。”

只有双方明确答应具体时间、地点和事项后，才使用约定标签。

- 朋友群消息

不要让所有角色同时发节日问候。
```

## WB-302 天气事件触发器

类型：事件层 / 天气触发  
配置建议：绿灯  
key 建议：`天气:晴,天气:多云,天气:阴,天气:小雨,天气:阵雨,天气:雷阵雨,天气:台风外围,天气:闷热,天气:晴热,天气:桂花香的晴天,天气:凉爽,天气:阴冷,天气:晴冷,天气:小雪,天气:湿冷`  
位置建议：角色定义后  
顺序建议：120  
需要用户填写：暂不需要。具体极端天气剧情、城市停运规则可后续补充  

严格格式部分：

- 不改变已确认时间、地点、资产、关系、物品。
- 不直接宣布角色因天气到达某地。
- 只作为环境、行程倾向和生活细节参考。

需要用户建议填写部分：

- 是否需要台风、暴雨、停课、停运等城市级事件。
- 哪些角色特别怕热、怕冷、喜欢雨天、讨厌出门。
- 哪些地点在雨天、雪天、节假日有特殊氛围。

```text
<澜景市天气事件触发器>
当前天气会影响澜景市的环境、交通、人流、店铺状态、角色外显状态和日程倾向。

天气只提供生活条件，不直接决定剧情结果。

【基本原则】

天气可以影响：
- 路面、空气、光线、气温
- 人流多少
- 交通速度
- 店铺营业氛围
- 角色穿搭和携带物
- 角色出门意愿
- 手机提醒、外卖、快递、约定变更
- 偶遇概率和等待体验

天气不能直接宣布：
- {{user}} 已经到达某地
- 角色已经改变位置
- 约定已经取消或成立
- 关系已经变化
- 物品已经损坏或丢失
- 长期地标已经改变

这些结果必须由剧情明确发生，并由对应记录确认。

【晴 / 多云 / 凉爽】
适合写通勤、散步、约见、户外排队、湖边或江边人流。
角色可以更愿意外出、绕路、闲聊、买饮品或分享周末安排。

不要每次都把天气写成风景描写。
只在天气影响当前互动时使用。

【小雨 / 阵雨 / 湿冷】
适合写雨伞、湿鞋、衣角、玻璃水痕、公交站拥挤、出门意愿下降、外卖和打车等待变久。
角色可以迟到、改约、提醒带伞、买热饮，或更愿意停留在室内地点。

雨天可以制造生活阻力，但不要强行制造灾难。
角色是否冒雨出门，应符合其性格、关系、日程和事情紧急程度。

【雷阵雨 / 台风外围】
适合写天色变暗、风大雨急、交通变慢、室外活动临时中断。
角色可以建议改到室内、推迟见面或确认安全。

台风外围不是完整台风灾害。
除非后续设定明确，不要写全城停摆、严重伤亡、长期断电或大规模破坏。

【晴热 / 闷热】
适合写空调房、冷饮、出汗、黏腻、午后疲惫。
商场、便利店、地铁站等室内地点人会更多。
角色可能减少户外停留，回复变短，耐心受影响，约见更倾向室内或傍晚。

热天影响状态，但不要把所有角色都写成暴躁。
不同角色对高温的反应应符合人设。

【桂花香的晴天】
适合写秋季街区气味、清澜弄、镜澜湖、校园、老街、花卉市场附近的生活感。
角色可以提到桂花糕、散步、拍照、买花、周末去处。

桂花香只是氛围和生活话题。
不要把它写成必然恋爱事件或命运暗示。

【阴冷 / 晴冷 / 小雪】
适合写围巾、热饮、手冷、呼出的白气、室内暖光、晚归、等车、店铺打烊、人流减少。
角色可能更想待在室内，或因关系亲近而提醒保暖。
小雪可以造成交通变慢、路面湿滑、迟到风险。

小雪可以增添氛围，但不要强行写成大雪封城。

【角色反应】

角色对天气的反应应结合：
- 人设
- 当前日程
- 身体状态
- 与 {{user}} 的关系
- 是否有约定
- 是否有必须完成的事

关系一般时，角色可能只是礼貌提醒。
关系亲近时，角色可能主动询问、送伞、改约、解释迟到。
关系紧张时，天气也可能只是维持距离的借口。

【天气与日程】

天气可以改变日程倾向，但不能替未确认的日程做决定。

可以写：
- “雨下起来后，她更可能留在室内。”
- “这个天气去江边的人少了些。”
- “消息发出后，对方暂时没有回复，或许还在路上。”

不要写：
- “因为下雨，她已经到了这里。”
- “因为闷热，她取消了所有安排。”
- “因为小雪，两人的关系自然升温。”

【天气与地点】

地点应根据天气呈现不同状态：
- 湖边、江边、山路、海岸线受风雨影响更明显。
- 商场、便利店、咖啡店、奶茶店在雨天和高温天更容易成为临时停留点。
- 山区、海边、桥梁、隧道、码头在恶劣天气下应更谨慎。

不要为了天气气氛永久改变地点。
长期破坏、施工、封路、改建等，应使用地标变更规则。
</澜景市天气事件触发器>
```
