# 比赛交互系统设计方案

## 核心原则

1. **比赛过程 = 纯 AIRP** — AI 自由发挥叙事，可以细到一个直道、一个弯道的描写，默认缓慢推进
2. **玩家操作 = 正常 RP 输入** — 玩家在酒馆输入栏正常打字，AI 根据回复推进比赛
3. **前端只负责显示** — 实时读取 MVU 变量（排名/圈数/共鸣值），不干预比赛过程
4. **比赛结算 = 前端计算** — 比赛结束后，前端根据最终排名自动计算固定奖励（奖金/积分/强化物品）

## 二、共鸣技能系统

### 2.1 共鸣值积累

共鸣值由 AI 在 MVU 变量更新中逐步增加，前端只负责显示。

### 2.2 共鸣技能释放

当共鸣值达到 100 时，前端弹出确认弹窗：

```
┌─ 共鸣技能就绪！ ──────────────────┐
│                                    │
│ 🌟 {技能名}                       │
│ {技能描述}                         │
│                                    │
│ 共鸣值已满，是否释放共鸣技能？      │
│                                    │
│     [暂不释放]    [释放！]          │
└────────────────────────────────────┘
```

- **释放**：前端将释放指令填入输入栏并自动发送
  ```
  （我决定释放共鸣技能「{技能名}」！描写共鸣技能释放的震撼场面和效果。释放后共鸣值归零。）
  ```
- **暂不释放**：关闭弹窗，玩家可以选择更好的时机手动释放

### 2.3 共鸣技能脚本（已有）

现有的 `脚本/共鸣技能/` 已经实现了共鸣值监听和弹窗逻辑，需要适配新的比赛面板。

## 三、比赛结算系统

### 3.1 触发时机

前端监听 MVU 变量变化：当 `世界.当前状态` 从 `'比赛中'` 变为 `'日常'` 时，自动触发结算。

### 3.2 结算计算（纯前端）

```typescript
function settleRace(data: Schema) {
  const tier = data.当前比赛.赛事级别;
  const rank = data.当前比赛.当前排名;
  const raceType = data.当前比赛.赛事类型;

  // 1. 计算奖金
  const prize = calculatePrize(tier, rank);
  data.主角.信用点数 += prize;

  // 2. 计算积分
  const points = calculatePoints(tier, rank);
  data.主角.赛季积分 += points;

  // 3. 发放强化物品
  const items = calculateEnhanceReward(tier, rank, raceType);
  items.forEach(item => addEnhanceItem(data, item));

  // 4. 清空比赛数据
  resetRaceData(data);
}
```

## 四、比赛中的前端行为总结

| 行为 | 由谁负责 | 说明 |
|------|---------|------|
| 比赛叙事推进 | AI | 纯 AIRP，AI 自由发挥 |
| 排名/圈数/共鸣值更新 | AI（MVU） | AI 在回复中通过 MVU 命令更新 |
| 比赛状态面板显示 | 前端 | 实时读取 MVU 变量渲染 |
| 共鸣技能释放确认 | 前端弹窗 | 共鸣值满时弹出，玩家选择时机 |
| 释放指令发送 | 前端 | 填入输入栏并发送 |
| 比赛结算计算 | 前端 | 奖金/积分/强化物品全部前端计算 |
| 结算结果展示 | 前端弹窗 | 显示所有奖励明细 |
| 结算变量写入 | 前端 | 直接修改 MVU 变量 |
