# 智脑重构项目清单

> 讨论定稿时间：2026-06-12
> 范围：明月秋青脚本 / 智脑系统重构方向
> 注意：本文只定义结构、流程、接口、占位与验收标准；所有具体内置预设提示词由用户另行手写。

## 0. 总目标

把当前智脑从“轻量召回 + 多模块提示词注入”重构为“分层事实账本 + 稳定摘要替代 + 精准召回”的系统。

核心目标：

- 召回更准，减少命中但权重不足的问题。
- 强化 AI 对剧情时间、地点、角色状态、重要物品的认知。
- 摘要不再作为额外噪音，而是作为隐藏楼层的替代内容。
- 允许增加 API 调用次数，用便宜模型处理小块事实，用好模型做周期性大总结。
- 保留梦呓现有效果，不改梦呓提示词和核心逻辑。
- 删除情绪积累和倒果为因，避免软判断影响动态人设和剧情权重。
- 所有提示词只留代码/文件位置占位，不在本次实现中编写具体内容。

## 1. 硬约束

- 不修改 `源码/prompts/*.txt` 的具体提示词文本，除非用户明确要求。
- 新增提示词文件时只放占位内容或空壳结构，具体提示词由用户后续手写。
- 删除所有“测试连接”按钮和逻辑，避免浪费公益站 token/次数。
- 模型列表采用用户主动点击“刷新模型列表”后拉取，不自动拉取。
- 模型列表需要缓存；接口不支持模型列表时只提示失败，不再追加测试请求。
- 正文生成永远是最高优先级，后台任务不得与正文抢 API。
- 后台任务必须串行，不允许并发调用 LLM。
- 用户发言后暂停启动新的后台任务；若已有后台请求发出，不强行中断，但下一项必须等待正文生成结束。
- 小总结、大总结使用独立 API 配置，不再受设置页原通用 API 覆盖。
- 设置页原 API 改为“通用后台 API”，只服务梦呓、关系网、世界推进、角色记忆更新等非小总结/大总结模块。

## 2. 删除模块

### 2.1 删除情绪积累

需要移除：

- `core/emotionAccumulation.ts`
- `index.ts` 中 `MESSAGE_SENT` 情绪计数与触发逻辑
- `CHAT_COMPLETION_SETTINGS_READY` 中情绪注入逻辑
- `mainStore.ts` 中 `emotionState` 相关类型、schema、computed、更新函数、返回项
- 设置页中的情绪开关与情绪间隔
- 任何依赖 `buildEmotionSummaryForPlotFate` 的代码

验收：

- 项目中不再出现用户可操作的“情绪积累”功能。
- 动态人设不再从情绪分析结果更新。
- 构建通过。

### 2.2 删除倒果为因

需要移除：

- `core/plotFate.ts`
- `index.ts` 中倒果分析触发和注入逻辑
- `mainStore.ts` 中 `plotFate` 相关类型、schema、computed、更新函数、返回项
- 设置页中的倒果为因开关
- 大总结后自动触发倒果的链路

验收：

- 项目中不再出现倒果为因功能。
- 大总结后不再触发未来剧情预测。
- 动态人设不受未来推演影响。

## 3. 保留模块

### 3.1 梦呓

保留：

- 梦呓数据结构
- 梦呓分析
- 梦呓注入
- 梦呓编辑 UI
- 梦呓撤回/恢复
- NSFW 梦呓隔离层

需要检查：

- 梦呓触发必须进入新的全局后台队列。
- 梦呓不得与正文生成抢 API。
- 梦呓仍在大总结后排队触发，但不阻塞正文。
- 梦呓的注入位置和现有效果尽量不动。

验收：

- 梦呓功能表现与当前版本一致。
- 后台队列中可看到梦呓任务。
- 用户正文生成期间不启动梦呓请求。

### 3.2 关系网

保留：

- 关系图展示
- 手动关系分析
- 世界书扫描
- 关系档案注入

调整定位：

- 关系网是提示词材料和展示层，不直接改角色记忆。
- 关系网不能喧宾夺主，不应强迫剧情进入敌对或极端关系。
- 具体关系提示词由用户后续改写。

验收：

- 关系网仍可展示当前关系。
- 关系档案可以作为本轮相关材料被状态包引用。
- 关系分析任务进入全局队列。

### 3.3 楼层隐藏

保留并升级：

- 已总结楼层隐藏
- 手动隐藏/取消隐藏
- 最新可见楼层保护

核心变化：

- 楼层隐藏系统成为“摘要替代系统”的基础。
- 未隐藏楼层不插入小总结。
- 已隐藏楼层才允许插入对应小总结。
- 已被大总结吸收的小总结不再插入，只插入大总结。
- 保持显示的楼层数量不做改变。

## 4. 新增：小总结 JSON 填表系统

### 4.1 功能定位

每轮 AI 正文结束后，用便宜模型对极小范围内容进行结构化填表，形成“小总结记录”。

建议模型定位：

- 便宜模型负责小总结，例如 GEMINI3F 一类低成本模型。
- 因为每次只处理少量内容，弱模型压力较小。
- 小总结只记录事实，不负责文学总结，不负责未来预测。

### 4.2 触发时机

默认：

- 每个 AI 楼层完成后生成 1 条小总结。
- 或每一轮用户+AI 形成一条小总结。

可配置：

- 自动小总结开关。
- 小总结批处理间隔。
- 失败重试次数。
- 失败后是否暂停队列。

### 4.3 小总结前端表格

新增表格 UI，用于展示和编辑小总结。

建议位置：

- 新增“总结引擎”Tab，或放在时光轴旁的子页。
- 小总结和大总结 API 配置放同一个页面。

表格能力：

- 按楼层范围筛选。
- 按状态筛选：可见、已隐藏、已吸收、失败、待生成。
- 展开查看 JSON。
- 手动编辑字段。
- 手动重新生成某条小总结。
- 手动标记错误/忽略。

## 5. 重构：大总结系统

### 5.1 功能定位

大总结不再直接承担所有事实提取压力，而是吸收小总结、必要原文、角色记忆、物品记忆，形成周期性归档。

建议模型定位：

- 好模型负责大总结，例如 3 Pro 一类高质量模型。
- 页面上提醒：大总结不要使用便宜弱模型。
- 不做测试连接。

### 5.2 触发逻辑

默认：

- 每 10 轮小总结后触发一次大总结。
- 或达到 N 条 ready 小总结后触发。

输入：

- 未被吸收的小总结。
- 对应隐藏楼层的原文或必要片段。
- 上一次大总结。
- 当前角色记忆库。
- 当前物品记忆库。
- 世界推进记录。

输出：

- 大时间线。
- 客观事实记录。
- 角色记忆更新材料。
- 物品记忆更新材料。
- 关系变化材料。
- 已吸收小总结范围。

### 5.3 小总结与大总结插入关系

规则：

- 0-10 楼未隐藏：不插入任何小总结。
- 0-2 楼已隐藏：只插入 0-2 对应小总结。
- 0-10 楼大总结完成：0-10 的小总结全部标记为 `absorbed`，不再插入。
- 大总结完成后，只插入该范围的大总结作为隐藏楼层替代。
- 未隐藏楼层继续保留原文，不重复插入摘要。

## 6. 新增：物品记忆库

### 6.1 功能定位

重要物品必须拥有独立记忆，避免剧情中物品名称、持有者、状态错乱。

小总结必须记录重要物品。

大总结必须归档物品记忆。

### 6.2 物品记忆数据结构草案

```ts

  itemName: string;
  aliases: string[];
  currentOwner: string;
  currentLocation: string;
  currentState: string;

    storyTime: string;
    event: string;
    floorRange?: string;
  }>;
  relatedCharacters: string[];
  openQuestions: string[];
  lastUpdatedAt: string;
}
```

### 6.3 物品合并逻辑

大总结需要处理：

- “玉佩”和“青玉坠”实际是同一物品。
- “短剑”和“那把剑”实际是同一物品。
- “钥匙”可能是多个不同物品，不能乱合并。

合并结果：

- 主名保留为 `itemName`。
- 其他名字进入 `aliases`。
- 历史记录合并去重。
- 当前持有者、位置、状态以最新可靠事实为准。

### 6.4 前端能力

角色库旁新增物品库，或新增“记忆库”子页。

能力：

- 查看物品列表。
- 查看物品历史。
- 编辑别名、持有者、位置、状态。
- 合并物品。
- 忽略误识别物品。
- 恢复忽略物品。

## 9. 新增：世界推进

### 9.1 名称

功能名确定为：世界推进。

替代旧后台行动推演/生态推演。

默认关闭。

### 9.2 功能定位

让世界不只随着正文在场角色推进，也让看不到的地方在同一时间切片内运转。

不是未来预测。

不是剧情规划。

只记录当前主时间线同一时段内，不在场角色最可能正在做什么。

### 9.3 触发逻辑

默认：

- 每 2 轮 AI 楼层触发一次。
- 进入全局后台队列。
- 正文生成期间不启动。

### 9.4 推进流程

1. 确认主时间线。
   - 当前剧情时间。
   - 当前地点。
   - 正文当前事件。
   - 世界当前信息，一句话。
2. 识别正文在场角色。
3. 从候选角色池中剔除在场角色。
4. 候选来源：
   - 角色库。
   - 关系网。
   - 世界书。
   - 最近被提及角色。
   - 有未完成目标的角色。
5. 按权重抽取少量角色。
   - 近期相关度。
   - 地点接近度。
   - 与当前事件关联度。
   - 与主角/在场角色关系强度。
   - 未完成行动。
6. 生成同时间切片内的行动。
   - 不能推进到未来时间。
   - 不能写“之后”“未来”“接下来将”。
   - 不能影响正文已发生事实。
7. 写入世界推进记录。
8. 后续被小总结、大总结、角色记忆更新吸收。

## 10. 新增：本轮状态包

### 10.1 功能定位

本轮状态包不是剧情指挥，不抢用户输入注意力。

它只是“事实校验表”。

作用：

- 防止错时。
- 防止错地点。
- 防止错角色状态。
- 防止错物品。
- 防止忘记隐藏楼层替代摘要。

### 10.2 防止抢权重原则

- 内容必须短。
- 只放本轮相关项。
- 不写剧情方向。
- 不要求 AI 围绕状态包展开。
- 使用“若涉及则不得违背”的语气。
- 不替代梦呓。
- 不替代用户输入。
- 不把所有大总结/角色库/关系网全塞进去。

### 10.3 注入层级建议

1. 隐藏楼层替代摘要放回聊天历史区域。
2. 已吸收范围使用大总结替代。
3. 本轮状态包靠近生成前，但保持短小。
4. 梦呓保持现有贴近用户输入的位置。
5. 角色事实、物品事实、关系事实只抽本轮相关。

## 11. 重构：摘要替代注入逻辑

### 11.1 旧逻辑问题

当前大总结作为提示词注入，容易和原文、梦呓、动态人设争权重。

### 11.2 新逻辑

摘要替代层根据楼层可见性决定插入内容：

- 楼层仍可见：不插入其小总结。
- 楼层已隐藏但未大总结吸收：插入小总结。
- 楼层已被大总结吸收：插入大总结。
- 最新保留楼层不改变。

### 11.3 需要新增的核心函数

建议新增模块：

- `core/contextReplacement.ts`

职责：

- 读取当前隐藏楼层。
- 计算哪些小总结处于 `hidden-active`。
- 计算哪些大总结需要替代被吸收范围。
- 组装替代内容。
- 插入到聊天历史区域。

### 11.4 验收

- 0-10 未隐藏时，不插小总结。
- 隐藏 0-2 时，只插 0-2 小总结。
- 大总结吸收 0-10 后，不再插 0-10 的小总结。
- 只插 0-10 大总结。
- 最新可见楼层数量不受影响。

## 13. 全局后台队列

### 13.1 队列显示位置

放到总览。

总览必须显示：

- 当前是否正文生成中。
- 当前正在执行的后台任务。
- 所有排队任务。
- 每个任务类型。
- 每个任务目标范围。
- 每个任务状态。
- 失败信息。
- 暂停/恢复状态。

任务类型：

- 小总结。
- 大总结。
- 梦呓。
- 世界推进。
- 角色记忆更新。
- 动态人设更新。
- 关系分析。
- 向量/索引任务，如果保留。

### 13.2 正文优先级

规则：

- 正文生成不是队列中的普通任务，而是最高优先级外部状态。
- 一旦检测到用户发言/正文生成准备开始，后台队列不得启动新任务。
- 正文完成后，后台队列继续。
- 后台任务之间串行。
- 不允许同时发多个 LLM 请求。

### 13.3 队列状态草案

```ts
interface BackgroundTask {
  id: string;
  type:
    | 'small_summary'
    | 'grand_summary'
    | 'dreamtalk'
    | 'world_progress'
    | 'character_memory_update'
    | 'dynamic_profile_update'
    | 'relationship_analysis'
    | 'embedding';
  label: string;
  priority: number;
  payload: unknown;
  status: 'queued' | 'running' | 'paused' | 'done' | 'failed' | 'cancelled';
  createdAt: string;
  startedAt?: string;
  finishedAt?: string;
  error?: string;
}
```

### 13.4 优先级建议

后台任务优先级从高到低：

1. 小总结。
2. 大总结。
3. 梦呓。
4. 角色记忆更新。
5. 动态人设更新。
6. 世界推进。
7. 关系分析。
8. 向量/索引。

正文生成始终高于以上所有任务。

## 17. 分阶段实施建议

- 总览显示完整队列。

验收：

- 删除模块后构建通过。
- 后台任务可在总览看到。
- 正文生成期间不启动后台任务。

### 阶段 2：总结引擎 API 与小总结表格

- 新增总结引擎 Tab。
- 新增小总结 API/模型配置。
- 新增大总结 API/模型配置。
- 实现模型拉取与缓存。
- 删除测试连接。

- 不会自动发测试请求。
- 小总结表格可展示和编辑。

### 阶段 3：小总结生成

- AI 楼层完成后排队生成小总结。
- 小总结失败可见。
- 可手动重试。
- 提示词仅占位。

验收：

- 新 AI 楼层可生成小总结记录。
- 小总结任务不与正文抢 API。

### 阶段 4：摘要替代层

- 实现隐藏楼层替代逻辑。
- 未隐藏不插小总结。
- 隐藏才插小总结。
- 大总结吸收后只插大总结。

验收：

- 用手动隐藏楼层测试替代插入。
- 最新可见楼层不变。

### 阶段 5：大总结 V2

- 大总结读取小总结。
- 生成 GrandSummaryV2。
- 吸收小总结。
- 归档角色记忆输入和物品记忆输入。

验收：

- 每 10 轮可生成大总结。
- 已吸收小总结不再插入。

### 阶段 6：物品记忆库

- 小总结记录重要物品。
- 大总结归档物品记忆。
- 新增物品库 UI。
- 支持物品合并。

验收：

- 同一物品不同名字可合并。
- 物品持有者、位置、状态可追踪。

### 阶段 7：角色记忆独立更新

- 每 2 AI 楼层排队更新角色记忆。
- 前端可编辑更新结果。
- 服务大总结体系。

验收：

- 角色记忆不再只依赖大总结生成。
- 记忆更新来源可追踪。

### 阶段 8：动态人设 V2

- 事实层 + 表现层。
- 移除全知倾向。
- 不再绑定情绪。
- 只从事实材料更新。

验收：

- 服装、位置、持有物等状态稳定。
- 不在场角色不会知道未知信息。

### 阶段 9：世界推进

- 新增世界推进模块。
- 默认关闭。

验收：

- 世界推进不会写未来时间。
- 在场角色被剔除。
- 推进记录可查看、编辑、忽略。

### 阶段 10：本轮状态包

- 组装短小事实校验表。
- 只注入本轮相关角色、物品、关系、世界推进。
- 不抢用户输入和梦呓注意力。

验收：

- 状态包长度可控。
- 召回事实更稳定。
- AI 不会围绕状态包过度展开。

## 18. 验收总标准

最终版本需要满足：

- 小总结、大总结、梦呓、世界推进、角色记忆更新都进入统一队列。
- 正文生成永远优先，后台不抢 API。
- 小总结只替代隐藏楼层，不重复污染可见原文。
- 大总结吸收后，小总结不再插入。
- 角色状态不再频繁错乱。
- 重要物品有独立记忆。
- 动态人设不再被情绪/未来推演带偏。
- 世界推进只推进同时间切片，不预测未来。
- 梦呓效果保持。
- 设置页 API 不再覆盖小总结/大总结。
- 所有具体提示词仍由用户手写。
