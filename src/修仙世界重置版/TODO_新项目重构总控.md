## 0. 当前总目标

把旧版《修仙世界》角色卡重构为新项目结构，玩法与工程方式参考《8bit的幻想》：

- 世界书不再一次性粗暴批量改写，而是先建立新世界观核心设定，再逐类、逐角色、逐条目确认。
- MVU 内容需要从旧变量体系迁移为更清晰的前端权威存档 / MVU 展示 / 世界书注入分工。
- 状态栏玩法需要更新为类似 8bit 的“前端结算 + 世界书精准注入 + 正文日志联动”结构。
- UI 美化放到世界书与玩法逻辑稳定之后，不提前抢跑。

## 1. 工作硬规则

- 不批量重写 871 条世界书。每次只处理一个明确范围：世界观、一个角色、一个势力、一个地点组或一个玩法模块。
- 每轮和用户聊完设定后，先更新本文记录，再改对应世界书 / schema / 状态栏文件。
- 用户确认通过的人设或地点设定，按旧世界书分类落盘到 `世界书重构版`；如果目标子路径不存在，由我自动一路创建。
- 修改 `世界书重构版/**/*.yaml` 时，禁止把“前端负责、脚本负责、状态栏、MVU、结算、事件协议、权威结果”等工程说明写进世界书正文；这些只能写进 `前端负责内容.md` 或调用逻辑资料。
- 每次修改世界书 yaml 后必须运行禁词检查，确认没有工程说明污染世界内提示词。
- 旧内容只作为素材池，不默认继承为新项目事实。凡是核心世界观、角色立场、主线方向、数值权威，都需要重新确认。
- 前端脚本负责权威结算：修炼、突破、战斗、掉落、物品、地图、关系、任务进度等不能只靠 AI 正文决定。
- 世界书负责硬事实、叙事素材、NPC 口吻、地点氛围、任务入口和禁写边界，不负责改变量或发奖励。
- 正文生成优先继承酒馆预设，参考 8bit 的 `generate` 正文链路；工具型草案才考虑 `generateRaw`。
- 所有新 ID、角色名、地点名、任务名、变量名需要可登记、可追踪、可复查。
