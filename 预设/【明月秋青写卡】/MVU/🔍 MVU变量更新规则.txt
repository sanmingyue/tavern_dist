# 变量规则自查清单

用户要求自查变量更新规则时，按此清单检查

## 检查项目

### 1. 精简变量更新规则

- [ ] 是否对变量名已经解释清楚该如何更新的自明变量填写了大量更新规则
- [ ] 是否有变量还能够合并变量更新规则

### 2. 变量更新结构

检查每个变量mapping：

- `z.record` 变量是否正确区分了变量路径和`type`中的键名
- `type`是否与变量结构脚本中的定义一致
- 是否有`check`字段

### 3. 特殊规则检查（如有）

如果有特殊系统（傲娇、敌意等），检查：

必需内容：
- 数值范围
- 变化步长
- 特殊条件
- 边界处理

错误：
- 没说范围
- 没说步长
- 规则不清晰

正确：
- 范围明确
- 步长清楚
- 特殊情况说明

### 4. 代码导入检查

确保代码中仅导入了 `import { registerMvuSchema } from 'https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/dist/util/mvu_zod.js';`, 没有导入 zod 或 lodash 库.

zod 和 lodash 库已经默认可用, 在代码中导入它们反而会导致问题.

### 5.条目设定提示检查

检查是否正确提示了世界书条目应该按如下设定：

条目配置（重要！这是特殊配置）：
- 条目名：[mvu_update]变量更新规则
- 条目名：[mvu_update]变量更新规则
- 条目名（一定不要忘记[mvu_update]）：[mvu_update]变量更新规则
- 位置：D齿轮在深度
- 深度：0
- 顺序：200
- 内容：把刚才输出的完整变量更新规则复制进去

## 检查输出格式

如果正确：

```
# 变量规则自查报告

规则结构正确，没有发现问题
```

如果有错误：

````
# 变量规则自查报告

发现以下问题：

1. ...

【修正后的变量更新规则规则】
```yaml
[完整的变量规则文件，从【变量更新】开始到最后一个example结束]
```
````

1. 只检查结构和格式正确性，不检查内容
7. 正确就说正确，不乱找问题
8. 给出具体错误和修正
9. 自查完必须输出配置说明
