# EJS代码自查清单

用户要求自查EJS代码时，按此清单检查

## 检查项目

### 1. 基础语法

检查项：
- 使用`<%_`而不是`<%`
- 使用`<%-`输出内容
- 所有`<%_`都有`_%>`
- 所有`<%`都有`%>`
- 没有用`print()`

错误示例：
```javascript
<% print(await getwi('条目')) %>
```

正确示例：
```javascript
<%- await getwi(null, '条目') %>
```

### 2. stat_data路径（重点）

**规则：EJS读取MVU变量必须有stat_data前缀**

检查所有`getvar()`：
- 有`stat_data.`前缀

错误示例：
```javascript
const value = getvar('角色.好感度');      // 缺stat_data
```

正确示例：
```javascript
const value = getvar('stat_data.角色.好感度', { defaults: 0 });
```

### 3. 防重复声明

检查项：
- 用`typeof`检查变量是否存在
- 用`var`而不是`const`/`let`

推荐写法：
```javascript
<%_
if (typeof affection === 'undefined') {
  var affection = getvar('stat_data.角色.好感度', { defaults: 0 });
}
_%>
```

### 4. 装饰器格式

检查项：
- 在内容开头
- 每行一个
- 之间没有空行
- 没有互斥组合（@@preprocessing 与 @@generate_before/after）

错误示例：
```javascript
@@generate_before

@@activate      // 有空行
```

正确示例：
```javascript
@@generate_before
@@activate
```

### 5. getwi调用

检查项：
- 第一个参数是`null`
- 有`await`
- 用`<%-`输出
- 条目名是字符串

错误示例：
```javascript
<%- getwi(null, '条目') %>          // 缺await
<%- await getwi('条目') %>          // 缺null
```

正确示例：
```javascript
<%- await getwi(null, '条目') %>
```

### 6. activewi调用

检查项：
- 第一个参数是`null`
- 有`await`
- 在`<%_`块内
- 配合`@@preprocessing`

错误示例：
```javascript
<%- await activewi(null, '条目', true) %>  // 用了<%-
```

正确示例：
```javascript
@@preprocessing
<%_
await activewi(null, '条目', true);
_%>
```

### 7. 条件判断

检查项：
- if语句正确闭合
- else if/else配对正确
- 没有缺`%>`或`<%`

### 8. 默认值

检查项：
- getvar使用`|| 默认值`
- 默认值类型正确

示例：
```javascript
const value = getvar('stat_data.角色.属性', { defaults: 0 });
const status = getvar('stat_data.角色.状态', { defaults: '正常' });
const list = getvar('stat_data.角色.列表', { defaults: [] });
```

### 9. 🚨 函数白名单检查（重点）

**扫描代码中所有函数调用，只能使用以下函数：**

**允许的函数**：
- `getvar()` `setvar()` `incvar()` `decvar()`
- `getwi()` `activewi()`
- `console.log()` `console.warn()` `console.error()` `console.info()`
- `toastr.info()` `toastr.success()` `toastr.warning()` `toastr.error()`
- JavaScript原生：`.includes()` `.endsWith()` `.startsWith()`

**禁止的函数（会报错）**：
- `require()` `import` `export`
- `JSON.parse()` `JSON.stringify()`
- `setTimeout()` `setInterval()` `clearTimeout()` `clearInterval()`
- `fetch()` `XMLHttpRequest` `axios`
- `fs.*` `path.*` 等Node.js模块
- `.filter()` `.map()` `.reduce()` 等数组方法（除非确认可用）
- 任何不在白名单的函数

**检查步骤**：
1. 逐行扫描代码
2. 找出所有函数调用（如`函数名(`）
3. 对比白名单

**发现非法函数立即报错**：

```
❌ 检测到非法函数：[函数名]

这个函数在SillyTavern EJS环境中不存在或不支持，代码无法运行

位置：[具体代码行]

修正方案：
- 如果是数据处理，考虑用简单的if/else替代
- 如果是网络请求，EJS不支持，需要其他方案
- 如果是文件操作，EJS不支持
- 移除或用白名单函数替代
```

### 10. 🚨 模板符合性检查（重点）

**检查代码是否符合📋 EJS模板库的6个模板之一**

**模板1-3特征（多阶段控制器）**：
- 有`if (typeof ... === 'undefined') var ... = getvar(...)`
- 有`if/else if/else`结构
- 有`<%- await getwi(null, '...') %>`

**模板4特征（动态关键词）**：
- 有`@@preprocessing`
- 有输出文本（关键词）
- 有条件判断

**模板5特征（日期判断）**：
- 有日期变量
- 有`.includes()`判断日期
- 有`<%- await getwi(null, '...') %>`

**模板6特征（状态栏）**：
- 有`@@render_after`或`@@render_before`
- 有`<%= 变量 %>`输出
- 简单的变量显示

**不符合模板的代码特征**：
- 复杂的对象操作（如`{}`字面量定义数据结构）
- 数组操作（`.filter()` `.map()` 等）
- 循环中的复杂逻辑
- 自定义的"聪明"写法

**检查步骤**：
1. 判断代码属于哪个模板
2. 检查结构是否符合该模板
3. 检查是否有"创新"写法

**发现不符合模板报错**：

```
❌ 代码结构不符合📋 EJS模板库

检测到的问题：
- [具体说明问题]

这段代码的写法：[描述不规范的地方]

正确的模板应该：[说明应该用哪个模板]

修正方案：
请参考📋 EJS模板库中的[模板X]，严格按照模板结构修改
```

### 11. 常见错误

检查项：
- 没在EJS中手写`stat_data`容器
- getvar路径正确（stat_data）
- 没用print()
- 装饰器格式正确
- getwi/activewi有await
- 括号配对正确
- 只使用白名单函数
- 代码符合模板库的某个模板
