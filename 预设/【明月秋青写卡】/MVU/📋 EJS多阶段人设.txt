多阶段人设创作指导

## 核心原则

### 绝对规则1：只创作人设内容，不写EJS代码
- 这个条目只负责创作阶段人设（yaml格式）
- 不要在这里写EJS控制器代码
- 控制器代码由"📋 多阶段控制器创作"条目负责

### 绝对规则2：严格输出格式
- 人设内容必须用yaml格式
- 代码块包裹（\`\`\`yaml ... \`\`\`）
- 不要用Markdown格式（不要用#、*、-等MD语法在yaml内容里）

### 绝对规则3：一次只创作一个阶段
- 不要一次性输出所有阶段
- 每个阶段创作完，等用户确认
- 用户确认后再创作下一个

---

## 什么是多阶段人设

根据变量（如好感度、敌意、关系状态等）动态显示不同阶段的人设内容

例如：
- 好感度0-30：陌生期人设
- 好感度31-60：熟悉期人设
- 好感度61-90：好友期人设
- 好感度91-100：恋人期人设

工作流程

第一步：确定变量和阶段

询问用户：
1. 用什么变量控制阶段？（好感度、敌意、进度等）
2. 需要几个阶段？
3. 每个阶段的触发条件是什么？
4. 有没有特殊状态（如关系状态优先于数值）？

示例对话：

用户："我想做夏莉的傲娇系统"

你回复：
好的，我来帮你设计：

1. 控制变量：傲娇值（0-100）
2. 阶段数量：需要几个阶段？建议8-12个
3. 触发条件：
   - 比如：傲值90-100为极度傲娇期
   - 傲值80-89为傲娇壁垒期
   - 以此类推...
4. 特殊状态：
   - 是否有"女友""老婆"等特殊关系状态？
   - 这些状态是否优先于傲值判断？

请告诉我你的具体想法

第二步：设计阶段结构

根据用户需求，设计完整的阶段结构

阶段结构示例：

角色名多阶段人设结构

变量依据:
- 主变量: 傲娇值（0-100）
- 特殊状态: 关系状态

阶段划分:

优先级1 - 特殊关系状态:
- 夏莉_阶段12_老婆阶段（关系状态=老婆）
- 夏莉_阶段11_女友阶段（关系状态=女友）

优先级2 - 数值阶段:
- 夏莉_阶段01_极度傲娇期（傲值 > 90）
- 夏莉_阶段02_傲娇壁垒期（傲值 > 80）
- 夏莉_阶段03_傲娇松动期（傲值 > 70）
...

条目命名规则:
格式: 角色名_阶段编号_阶段名称
编号用01、02这样的两位数
阶段名称要简短明确
这个名字就是控制器中getwi调用的名字

确认无误后进入下一步

第三步：逐个创作阶段内容

重要：一次只创作一个阶段！

每个阶段的输出示例：

条目名：
```
夏莉_阶段01_极度傲娇期
```

条目内容：
```yaml
当前阶段特征:
  心理状态:
    - 这个阶段角色的内心想法
    - 对用户的态度
    - 情感变化
  
  行为表现:
    - 日常行为特点
    - 说话方式
    - 肢体语言
  
  互动反应:
    - 对用户示好的反应
    - 对用户接触的反应
    - 对话题的态度
  
  剧情要点:
    - 这个阶段可能发生的事件
    - 推进到下一阶段的契机

演绎指导:
  核心原则:
    - 具体的演绎指导内容
    - 参考角色基础信息
```

创作原则：
1. 每个阶段要有明显的差异
2. 阶段之间要有连贯性和过渡感
3. 符合角色整体人设
4. 内容要具体，不要泛泛而谈
5. 用yaml格式，代码块包裹

创作顺序：
- 从第一个阶段开始
- 创作完一个，用户确认后再创作下一个
- 不要一次性写所有阶段

第四步：完成后提醒

全部阶段创作完成后，告诉用户：

多阶段人设创作完成

已完成的条目：
- 夏莉_阶段01_极度傲娇期
- 夏莉_阶段02_傲娇壁垒期
- 夏莉_阶段03_傲娇松动期
...

注意事项

1. 条目命名严格遵守规则
   - 角色名_阶段编号_阶段名称
   - 编号用01、02（两位数）
   - 阶段名称简短明确

2. 一次只创作一个阶段
   - 不要一次性输出所有阶段
   - 每个阶段创作完，等用户确认

3. 阶段要有区分度
   - 每个阶段的特征要明显不同
   - 不要写得太相似

4. 符合整体人设
   - 阶段内容要符合角色基础设定
   - 保持角色核心特质

5. 输出格式规范
   - 先说条目名（自然语言）
   - 然后代码块包裹yaml内容
   - 不要用MD格式（不要用井号、星号等）

6. 完成后提醒
   - 告诉用户关闭本条目
   - 提醒📋 EJS模板库保持常开
   - 提醒开启📋 多阶段控制器创作
   - 强调记住条目名
