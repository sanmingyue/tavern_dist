小白X Varevent世界书条目自查清单

当用户要求自查Varevent条目时，使用此清单进行全面检查。

检查项目

1. 代码块纯净度检查

代码块内只能有条目内容本身，不能有任何额外内容！

代码块内没有注释（如 // 这是注释 或 # 注释）
代码块内没有说明文字（如 "以下是Varevent条目："）
代码块内没有空行或多余换行（除了event之间的空行）
代码块内没有 markdown 格式
内容直接以 <varevent> 开头

错误示例：
```
// Varevent条目
<varevent>
...
</varevent>
```

```
以下是触发事件：
<varevent>
...
</varevent>
```

正确示例：
```
<varevent>

[event.1]
condition: var(`状态.天气`) === "晴朗"
display: "阳光明媚，是个出门的好天气。"

</varevent>
```

2. varevent标签检查

必须使用尖括号 <>，不是方括号 []
标签名称必须是 varevent，全小写
开始标签 <varevent> 和结束标签 </varevent> 必须成对出现
varevent内部禁止出现其他 <> 标签

错误示例：
[varevent]        ← 方括号错误
<Varevent>        ← 大小写错误
<var-event>       ← 格式错误
<varevent></var>  ← 标签不匹配

正确示例：
<varevent>
...
</varevent>

3. event标识格式检查

格式必须是 [event.数字]
数字从1开始递增
方括号包裹

错误示例：
[event1]          ← 缺少点号
[event.01]        ← 不要补零
event.1           ← 缺少方括号
[Event.1]         ← 大小写错误

正确示例：
[event.1]
[event.2]
[event.3]

4. condition条件格式检查

condition: 后面跟条件表达式
变量路径必须用 var(`路径`) 格式
路径用反引号 ` 包裹，不是单引号 '

错误示例：
condition var(`路径`) >= 10       ← 缺少冒号
condition: var('路径') >= 10      ← 用了单引号而不是反引号
condition: var(路径) >= 10        ← 缺少反引号
condition: 路径 >= 10             ← 缺少var()

正确示例：
condition: var(`状态.天气`) === "晴朗"
condition: var(`角色.好感度`) >= 50

5. 数值比较写法检查

简单数值比较不需要parseInt（系统自动类型转换）
只有数学计算（加减乘除）才需要parseInt
防空值 || 0 必须用括号包裹

错误示例：
condition: parseInt(var(`好感度`)) >= 50              ← 简单比较不需要parseInt
condition: var(`数值1`) + var(`数值2`) >= 10          ← 数学计算需要parseInt
condition: parseInt(var(`数值`)) || 0 >= 10           ← 缺少括号

正确示例：
condition: var(`好感度`) >= 50
condition: (parseInt(var(`数值1`)) + parseInt(var(`数值2`))) >= 10
condition: (parseInt(var(`数值`)) || 0) >= 10

6. display内容格式检查

display: 后面跟英文双引号包裹的文本
必须使用英文双引号 " "，不是中文引号 " "
display内容不能为空

错误示例：
display "文本内容"                ← 缺少冒号
display: 文本内容                 ← 缺少引号
display: '文本内容'               ← 用了单引号
display: "文本内容"               ← 用了中文引号
display: ""                       ← 内容为空

正确示例：
display: "阳光明媚，是个出门的好天气。"

7. js_execute命令格式检查

单命令格式：
js_execute: "STscript('/xbsetvar ...')"

多命令格式（推荐）：
js_execute: "(async()=>{ await STscript('...'); await STscript('...'); })()"

$range必须包含完整范围值如[0,100]
带$range的路径需要用\"转义引号
纯字符串值不需要额外引号
禁止用管道符|连接多个命令

错误示例：
js_execute: "STscript('/xbsetvar \"$range= 路径\" 值')"           ← $range缺少范围值
js_execute: "STscript('/xbsetvar ... | /xbsetvar ...')"           ← 管道符错误
js_execute: "STscript('/xbsetvar 角色.关系 \"信赖\"')"            ← 纯字符串不需要额外引号

正确示例：
js_execute: "STscript('/xbsetvar \"$range=[0,100] 角色.好感度\" 70')"
js_execute: "(async()=>{ await STscript('/xbsetvar \"$range=[0,100] 角色.好感度\" 70'); await STscript('/xbsetvar 角色.关系 信赖'); })()"

8. 代码块结束格式检查

</varevent> 后必须换行再写 ```
禁止 </varevent>``` 连在一起

错误示例：
```
<varevent>
...
</varevent>```
```

正确示例：
```
<varevent>
...
</varevent>
```

9. 阶段性事件排列检查

同一varevent块内，阶段性条件从低到高排列
高阶事件在后，自动覆盖低阶
独立事件要分开写多个varevent块

错误示例（阶段顺序错误）：
```
<varevent>

[event.1]
condition: var(`体力`) >= 70      ← 高阶在前，错误
display: "精力充沛"

[event.2]
condition: var(`体力`) >= 30      ← 低阶在后，错误
display: "有些疲惫"

</varevent>
```

正确示例：
```
<varevent>

[event.1]
condition: var(`体力`) >= 0       ← 最低阶在前
display: "精疲力竭"

[event.2]
condition: var(`体力`) >= 30      ← 中阶
display: "有些疲惫"

[event.3]
condition: var(`体力`) >= 70      ← 高阶在后
display: "精力充沛"

</varevent>
```

10. 常见错误检查

varevent标签用了方括号而不是尖括号
condition缺少冒号
变量路径用单引号而不是反引号
简单比较误用parseInt
display用了单引号或中文引号
js_execute的$range缺少范围值
js_execute用管道符连接命令
</varevent>后没有换行就写```
阶段性条件顺序错误（高阶在前）

检查输出格式

如果条目完全正确，输出：

```
小白X Varevent条目自查报告

条目格式正确，没有发现问题。

事件数量：X个
条件类型：数值比较/字符串匹配/逻辑组合
是否含js_execute：是/否
```

如果发现错误，按以下格式输出：

```
小白X Varevent条目自查报告

发现以下格式错误：

1. 标签格式错误：
   [varevent] 应改为 <varevent>

2. condition格式错误：
   var('路径') 应改为 var(`路径`)

3. display格式错误：
   用了中文引号，应改为英文双引号

4. js_execute格式错误：
   $range缺少范围值，应写为 $range=[0,100]

修正后的条目：
```
<varevent>
...
</varevent>
```
```

自查原则

只检查格式错误：标签、condition语法、display引号、js_execute格式
不检查内容合理性：假定用户已经设计好触发逻辑
如果正确就说正确：不要为了检查而找问题
给出理由：说明为什么这是错误的
提供修正方案：如果有错误，直接给出修正后的条目

快速参考

基本结构：
```
<varevent>

[event.1]
condition: var(`路径`) >= 数值
display: "显示内容"

[event.2]
condition: var(`路径`) === "文本"
display: "显示内容"
js_execute: "STscript('命令')"

</varevent>
```

条件写法：
var(`路径`) >= 数值                              简单数值比较
var(`路径`) === "文本"                           字符串精确匹配
var(`路径`).includes("关键词")                   字符串包含
条件1 && 条件2                                   与（都满足）
条件1 || 条件2                                   或（满足其一）
(parseInt(var(`a`)) + parseInt(var(`b`))) >= 10  数学计算

js_execute写法：
单命令：js_execute: "STscript('/xbsetvar \"$range=[0,100] 路径\" 值')"
多命令：js_execute: "(async()=>{ await STscript('命令1'); await STscript('命令2'); })()"
