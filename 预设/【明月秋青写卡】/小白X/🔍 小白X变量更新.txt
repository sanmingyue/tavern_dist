小白X变量更新世界书条目自查清单

当用户要求自查小白X变量更新条目时，使用此清单进行全面检查。

检查项目

1. 代码块纯净度检查

代码块内只能有条目内容本身，不能有任何额外内容！

代码块内没有注释（如 // 这是注释 或 # 注释）
代码块内没有说明文字（如 "以下是更新条目："）
代码块内没有空行或多余换行
代码块内没有 markdown 格式
内容直接开始，前面没有任何字符

错误示例：
```
// 变量更新条目
你需要在每次回复末尾更新变量。
...
```

```
以下是更新规则：
你需要在每次回复末尾更新变量。
...
```

正确示例：
```
你需要在每次回复末尾更新变量。
...
```

2. 标签格式检查

使用尖括号，不是方括号或其他符号：
<plot-log> 和 </plot-log> 正确
<varthinking> 和 </varthinking> 正确
标签必须成对出现
标签名称拼写正确

错误示例：
[plot-log]  ← 方括号错误
<plotlog>   ← 缺少连字符
<plot_log>  ← 下划线错误
<Plot-Log>  ← 大小写错误

正确示例：
<plot-log>
{...}
</plot-log>

3. JSON格式检查

JSON语法正确（括号、逗号、引号配对）
最后一个元素后没有多余逗号
所有键名都用双引号包裹
所有字符串值都用双引号包裹
使用英文双引号，不是中文引号

错误示例：
{"记下": {"状态.天气": "晴天",}}     ← 多余逗号
{记下: {"状态.天气": "晴天"}}        ← 键名没有引号
{"记下": {状态.天气: "晴天"}}        ← 路径没有引号

4. 操作关键词检查

只能使用以下四个操作关键词：
记下：设置变量值（修改现有值或新增对象键）
调整：数值增减（正数增加，负数减少）
追加：向数组添加元素
删除：移除变量键或数组元素

不能使用其他关键词（如：更新、修改、设置、增加等）

错误示例：
```
{
  "更新": {"状态.天气": "晴天"}      ← 错误关键词
}
```

```
{
  "设置": {"状态.天气": "晴天"}      ← 错误关键词
}
```

正确示例：
```
{
  "记下": {"状态.天气": "晴天"}
}
```

5. 路径格式检查

路径格式：顶层key.子键.子键
路径用点号分隔
路径不包含$规则前缀
路径用双引号包裹

错误示例：
"$ext 角色.三明月.好感度"    ← 包含$规则前缀
"角色/三明月/好感度"         ← 用了斜杠
"角色三明月好感度"           ← 没有分隔符
角色.三明月.好感度           ← 没有引号

正确示例：
"角色.三明月.好感度"
"状态.天气"
"系统.金币"

6. 操作与值类型匹配检查

记下：值可以是字符串、数值、对象
调整：值必须是数值（正数或负数）
追加：值必须是数组格式
删除：值为要删除的键名或数组元素

错误示例：
```
{
  "调整": {"角色.三明月.好感度": "增加5"}    ← 调整的值应该是数值
}
```

```
{
  "追加": {"角色.三明月.回忆": "新回忆"}     ← 追加的值应该是数组
}
```

正确示例：
```
{
  "调整": {"角色.三明月.好感度": 5}
}
```

```
{
  "追加": {"角色.三明月.回忆": ["新回忆"]}
}
```

7. varthinking格式检查（完整格式）

分析JSON中末端变量标记 Yes 或 No
父变量无需更新则折叠为 No
分析JSON结构与变量结构对应
分析JSON在前，plot-log在后

错误示例：
```
<varthinking>
<plot-log>
{...}
</plot-log>
{分析JSON}           ← 顺序错误，分析应在前
</varthinking>
```

正确示例：
```
<varthinking>
{
  "状态": {
    "天气": "Yes",
    "时间": "No"
  }
}
<plot-log>
{
  "记下": {"状态.天气": "晴天"}
}
</plot-log>
</varthinking>
```

8. 单一plot-log检查

每次回复只能有一个 <plot-log> 模块
所有变量更新必须合并在同一个 plot-log 内
禁止输出多个 plot-log

错误示例：
```
<plot-log>
{"记下": {"状态.天气": "晴天"}}
</plot-log>
<plot-log>
{"调整": {"角色.三明月.好感度": 2}}
</plot-log>
```

正确示例：
```
<plot-log>
{
  "记下": {"状态.天气": "晴天"},
  "调整": {"角色.三明月.好感度": 2}
}
</plot-log>
```

9. 示例完整性检查（针对更新条目模板）

示例是否涵盖了所有末端变量
有数值变量是否包含调整示例
有$grow/$list数组是否包含追加示例
有$shrink/$list数组是否包含删除数组元素示例
有$ext/$free对象是否包含记下新增键示例
有$prune/$free对象是否包含删除对象键示例

10. 常见错误检查

标签名称拼写错误（plot-log 不是 plotlog）
操作关键词错误（记下 不是 更新/设置/修改）
路径包含$规则前缀
调整操作的值不是数值
追加操作的值不是数组
多个plot-log模块
JSON语法错误（逗号、引号、括号）
中英文标点混用

检查输出格式

如果条目完全正确，输出：

```
小白X变量更新条目自查报告

条目格式正确，没有发现问题。

条目类型：简单格式/完整格式
涵盖操作：记下、调整、追加、删除（列出实际包含的）
```

如果发现错误，按以下格式输出：

```
小白X变量更新条目自查报告

发现以下格式错误：

1. 标签格式错误：
   [plot-log] 应改为 <plot-log>

2. 操作关键词错误：
   "更新" 应改为 "记下"

3. 路径格式错误：
   "$ext 角色.三明月" 路径中不应包含$规则前缀

4. 值类型错误：
   "调整" 操作的值应该是数值，不是字符串

修正后的条目：
```
你需要在每次回复末尾更新变量。
...
```
```

自查原则

只检查格式错误：标签、JSON语法、操作关键词、路径格式
不检查内容丰富度：假定用户已经完成所有需求设计
如果正确就说正确：不要为了检查而找问题
给出理由：说明为什么这是错误的
提供修正方案：如果有错误，直接给出修正后的条目

快速参考

四种操作关键词：
记下 - 设置变量值，如 "记下": {"状态.天气": "晴天"}
调整 - 数值增减，如 "调整": {"角色.三明月.好感度": 5}
追加 - 数组添加，如 "追加": {"角色.三明月.回忆": ["新事件"]}
删除 - 移除变量，如 "删除": {"角色.三明月.临时状态": null}

简单格式示例：
```
你需要在每次回复末尾更新变量。

四种操作关键词

更新格式

{
  "操作关键词": {
    "路径": 值
  }

</plot-log>
```

完整格式示例：
```
你需要在每次回复末尾更新变量。

四种操作关键词
记下：直接设置变量值
调整：数值增减
追加：向数组添加元素
删除：移除变量键或数组元素

更新格式

</plot-log>
</varthinking>
```
