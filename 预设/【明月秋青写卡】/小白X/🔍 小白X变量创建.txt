小白X变量初始化脚本自查清单

当用户要求自查小白X变量初始化脚本时，使用此清单进行全面检查。

检查项目

1. 代码块纯净度检查

代码块内只能有命令本身，不能有任何额外内容！

代码块内没有注释（如 // 这是注释 或 # 注释）
代码块内没有说明文字（如 "以下是初始化脚本："）
代码块内没有空行或多余换行
代码块内没有 markdown 格式
命令直接以 /xbsetvar 开头，前面没有任何字符

错误示例：
```
// 变量初始化脚本
/xbsetvar key=角色 {...}
```

```
以下是初始化命令：
/xbsetvar key=角色 {...}
```

```
# 角色变量
/xbsetvar key=角色 {...}
```

正确示例：
```
/xbsetvar key=角色 {"好感度": 50}
```

2. 命令格式检查

基本格式必须正确：
```
/xbsetvar key=顶级键名 {JSON对象}
```

命令以 /xbsetvar 开头
key= 后面紧跟顶级键名（无空格）
顶级键名后有空格，然后是JSON对象
多个命令用 | 分隔（注意前后有空格）

错误示例：
```
/xbsetvar key= 角色 {...}     ← key=后面有空格
/xbsetvar key=角色{...}       ← 键名和JSON之间没有空格
/xbsetvar 角色 {...}          ← 缺少key=
```

正确示例:
/xbsetvar key=角色 {"好感度": 50}
/xbsetvar key=状态 {...} | /xbsetvar key=角色 {...}

3. JSON格式检查

JSON语法正确（括号、逗号、引号配对）
最后一个元素后没有多余逗号
所有键名都用双引号包裹
所有字符串值都用双引号包裹
JSON写在同一行（不能换行）
使用英文双引号，不是中文引号

错误示例:
{"好感度": 50,}              ← 多余逗号
{好感度: 50}                 ← 键名没有引号
{"好感度": "五十"}           ← 中文引号（如果是）

4. 规则前缀格式检查

规则前缀必须写在键名前面，用空格分隔：
$range=[最小,最大] 格式正确（方括号，逗号分隔）
$ext / $free / $prune 拼写正确
$grow / $shrink / $list 拼写正确
$min=数字 / $max=数字 格式正确
$enum={选项1;选项2} 格式正确（花括号，分号分隔）
规则前缀和键名之间有空格

错误示例：
```
{"$range[0,100] 好感度": 50}      ← 缺少等号
{"$range=[0-100] 好感度": 50}     ← 用了连字符而不是逗号
{"$range=[0,100]好感度": 50}      ← 规则和键名之间没有空格
{"$rang=[0,100] 好感度": 50}      ← 拼写错误
{"$ext角色A": {...}}              ← 规则和键名之间没有空格
```

正确示例：
```
{"$range=[0,100] 好感度": 50}
{"$ext 角色A": {"$range=[0,100] 好感度": 70}}
{"$grow 事件记录": []}
```

5. 嵌套结构检查

嵌套对象的括号正确配对
每层嵌套的规则前缀位置正确
数组用方括号 []，对象用花括号 {}

嵌套示例：
```
{"$ext 角色列表": {"$free 角色A": {"$range=[0,100] 好感度": 70, "穿着": "白裙"}}}
```

解析：
角色列表 → $ext → 可新增角色，不可删除
角色A → $free → 属性可自由增删
好感度 → $range → 限制在0-100

6. 数值范围检查

$range=[最小,最大] 中最小值小于最大值
初始值在范围内
$min 和 $max 不冲突

错误示例：
```
{"$range=[100,0] 好感度": 50}     ← 最小值大于最大值
{"$range=[0,100] 好感度": 150}    ← 初始值超出范围
```

7. 数组初始化检查

数组使用方括号 []
空数组写为 []
数组元素格式正确

正确示例：
```
{"$grow 事件记录": []}
{"$list 物品": ["药水", "钥匙"]}
```

8. 管道符分隔检查

多个 /xbsetvar 命令：
用 | 分隔（前后有空格）
每个命令格式完整
不要在JSON内部使用管道符

错误示例：
```
/xbsetvar key=状态 {...}|/xbsetvar key=角色 {...}    ← 管道符前后没有空格
```

正确示例：
```
/xbsetvar key=状态 {...} | /xbsetvar key=角色 {...}
```

9. 常见错误检查

规则前缀拼写正确（$range 不是 $rang）
等号使用正确（$range= 不是 $range:）
方括号和花括号使用正确
没有使用中文标点符号
没有多余的空格或缺少必要的空格
字符串值没有遗漏引号
数值没有错误地加引号（除非故意存为字符串）

10. 规则使用合理性检查

好感度等数值使用了 $range 限制
需要动态添加的对象使用了 $ext 或 $free
只增不减的数组使用了 $grow
没有滥用 $ro（只读）
没有不必要地使用 $enum

11. 初始值合理性检查

初始值类型与预期用途匹配
数值初始值合理（好感度初始50？还是0？）
字符串初始值有意义
空数组/空对象使用正确

检查输出格式

如果脚本完全正确，输出：

```
小白X变量初始化脚本自查报告

脚本格式正确，没有发现问题。

脚本结构：
key=状态：包含天气、时间、地点
key=角色：包含角色A（好感度、穿着）
key=系统：包含金币、事件记录
```

如果发现错误，按以下格式输出：

```
小白X变量初始化脚本自查报告

发现以下格式错误：

1. 命令格式错误：
   key=后面有多余空格

2. JSON格式错误：
   第X处缺少逗号
   键名"好感度"没有用双引号包裹

3. 规则前缀错误：
   "$rang" 应改为 "$range"
   "$range=[0,100]好感度" 规则和键名之间缺少空格

4. 数值范围错误：
   好感度初始值150超出范围[0,100]

修正后的脚本：
```
/xbsetvar key=状态 {...} | /xbsetvar key=角色 {...}
```
```

自查原则

只检查格式错误：命令格式、JSON语法、规则前缀拼写
不检查内容丰富度：假定用户已经完成所有需求设计
如果正确就说正确：不要为了检查而找问题
给出理由：说明为什么这是错误的
提供修正方案：如果有错误，直接给出修正后的脚本

快速参考

可用规则前缀：

$range=[a,b] 数值范围限制，如 $range=[0,100] 好感度
$min=数 最小值限制，如 $min=0 金币
$max=数 最大值限制，如 $max=999 生命
$ext 对象可新增键，如 $ext 角色列表
$prune 对象可删除键，如 $prune 临时数据
$free 对象可增可删，如 $free 角色A
$grow 数组只增不减，如 $grow 事件记录
$shrink 数组只减不增，如 $shrink 任务列表
$list 数组可增可删，如 $list 物品栏
$enum={A;B;C} 枚举限制，如 $enum={晴;雨;雪} 天气
$ro 只读锁定，如 $ro 真名

完整示例

```
/xbsetvar key=状态 {"天气": "晴朗", "时间": "上午", "地点": "教室"} | /xbsetvar key=角色 {"$ext 角色列表": {"$free 角色A": {"$range=[0,100] 好感度": 50, "穿着": "校服", "$grow 回忆": []}}} | /xbsetvar key=系统 {"$range=[0,99999] 金币": 1000, "$grow 剧情事件": []}
```
